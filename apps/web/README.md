# Uteum Mail — 웹 프로토타입

S1~S9 핵심 여정을 가상 계정·메일과 정해진 비서 응답으로 체험하는 프런트엔드입니다. 실제 인증 정보와 API 키가 필요하지 않습니다.

## 실행

Node.js 24 LTS와 npm을 사용합니다.

```bash
cd apps/web
npm ci
npm run dev
```

개발 화면은 [http://127.0.0.1:3000](http://127.0.0.1:3000)입니다. 개발 서버와 프로덕션 서버는 기본적으로 로컬 컴퓨터에서만 접근할 수 있습니다.

```bash
npm run build
npm run start -- --port 3001
```

프로덕션 화면은 [http://127.0.0.1:3001](http://127.0.0.1:3001)입니다. 서로 다른 포트의 체험 자료는 브라우저에 별도로 저장됩니다.

## 체험 흐름

1. **오늘 → 통합 메일함**에서 라온 스튜디오의 견적 요청을 엽니다.
2. 연결된 업무 후보를 채택하고 원문을 확인합니다.
3. 답장 초안을 준비하고 편집·저장한 뒤 **모의 발송**을 누릅니다. 발송 후에도 자료 전달 등 남은 업무는 유지됩니다.
4. 비서의 **앞으로 라온 견적은 중요하게**로 규칙을 만들고 **분류 규칙**에서 수정·중지·되돌리기를 확인합니다.
5. **서비스·수신 관리**에서 마케팅 해제의 접수·실패·직접 설정 필요 결과를 확인합니다.

- **가상 계정 추가 → 처음부터 체험**으로 계정 연결 모의 처리와 시작 설정을 확인합니다.
- **체험 설정**에서 분석 대기·실패, 연결 만료, 부분 실패, 발송 미확인, 빈 상태를 재현할 수 있습니다. 시나리오 전환은 현재 가상 자료를 해당 시나리오의 원본으로 교체합니다.
- **설정**에서 AI 끄기, 연결 해제, 보관 자료 삭제를 각각 체험할 수 있습니다.
- 준비된 질문과 지원되는 짧은 입력에만 응답합니다. 지원되지 않는 입력은 체험할 수 있는 요청을 안내합니다.

## 자료와 저장

- 시연 기준 시각: **2026-10-03 09:00 Asia/Seoul**. 실제 오늘 날짜와 관계없이 반복 가능한 자료를 사용합니다.
- 저장 키: `uteum-mail.prototype.v1`. 현재 브라우저·주소의 localStorage에 수정 결과를 저장합니다.
- 저장이 차단되면 메모리에서 계속 동작하고 저장 불가 안내를 표시합니다. 손상된 자료는 자동으로 덮어쓰지 않으며 데모 초기화로 복구합니다.
- 새로고침 시 진행 중 분석·초안 준비는 재시도 상태, 진행 중 발송은 결과 미확인 상태로 복원합니다.
- 데모 초기화는 체험 전용 자료만 복원합니다. 다른 브라우저 저장 항목에는 영향을 주지 않습니다.

## 구조

| 경로 | 책임 |
| --- | --- |
| `src/app` | 화면 경로·레이아웃·공통 스타일 |
| `src/components` | 탐색 틀·체험 제어·shadcn/ui 컴포넌트 |
| `src/features` | 메일·업무·초안·비서·규칙·수신·설정 화면 |
| `src/lib/prototype` | 타입·합성 자료·상태 전환·저장·가상 접근·준비된 응답 |
| `tests/prototype.test.ts` | 상태·중복 처리·늦은 결과·저장·삭제 회귀 검사 |
| `public/demo` | 직접 만든 가상 첨부 예시 |

화면은 공통 스토어의 스냅샷을 조회하고, Promise를 반환하는 가상 접근 계층을 통해 변경합니다. 실제 Spring API의 권한·처리 계약은 이후 별도로 설계합니다.

## 검증 명령

```bash
npm test
npm run typecheck
npm run lint
npm run build
```

메일 연결·발송·수신 해제는 모의 처리입니다. 모델·임베딩·Spring·FastAPI·DB·클라우드 서비스 호출은 구현하지 않았습니다. 첨부 예시는 이 저장소의 정적 파일이며 실제 파일 업로드가 아닙니다. 이 화면의 준비된 응답과 가상 지연으로 운영 AI 품질·동기화·가용성을 판단할 수 없습니다.

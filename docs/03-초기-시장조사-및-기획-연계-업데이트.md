## 2. 현재까지의 핵심 판단

1. **유사한 상용 서비스가 이미 존재한다.** 메일 통합, AI 검색·요약·작성, 일정 처리, 팀 업무 자동화가 각각 또는 함께 제공되고 있다.
2. **비서가 전문 에이전트를 조율하는 구조도 공개 사례가 있다.** 따라서 멀티에이전트라는 구조만으로 독점적 차별성을 주장하기 어렵다.
3. **경쟁사의 존재 자체가 출시를 금지하지는 않는다.** 다만 저작권·특허·상표, 개인정보 처리, 메일 제공사의 정책은 별개로 검토해야 한다.
4. **이메일 AI에 돈을 지불하는 시장의 신호는 있지만, 한국의 혼합 메일 사용자 수요는 미검증이다.** 해외 업체의 공개 매출을 국내 사업성으로 곧바로 일반화할 수 없다.
5. **범용 통합 이메일＋멀티에이전트만으로 개발 투자를 결정하기에는 차별성이 부족하다.** 특정 고객의 손실을 유발하는 누락 업무로 범위를 좁혀 검증할 가치는 있다.

현재 권고는 통합 조회·광고 수신 관리·중요 메일 분류와 후속 업무 추적을 대상으로 고객 수요와 기존 제품 대비 효과를 검증하는 것이다. 출시 성공 가능성이나 법적 비침해를 확정한 결론은 아니다.

### 멀티에이전트 구조의 직접적인 공개 사례

Ability.ai의 Corbin은 이메일·일정·CRM·문서를 다루는 비서가 **14개 전문 하위 에이전트에 일을 위임하고 결과를 종합한다**고 설명한다. 정기 브리핑, 메일 분류, 검토용 답장 초안도 포함한다.

이는 구상 중인 오케스트레이터 비서와 구조적으로 가깝다. 다만 고객 환경에 구축하는 형태이며, 공급사의 공개 설명을 확인한 수준이다. 대중적인 구독 앱으로서의 시장 규모나 성능까지 검증된 사례로 보지는 않는다.

Spark·Missive 등은 공개된 사용자 기능만으로 내부가 단일 에이전트인지 멀티에이전트인지 판단할 수 없다. 내부 구조가 공개되지 않았다는 이유로 해당 구조를 사용하지 않는다고 단정해서는 안 된다.

### 4.2 구독·연결 관리의 기존 기능과 구현 범위 — 2026-09-24

Gmail은 구독 목록을 모아 보고 수신 해제를 실행하는 기능을 안내한다. 발신자 차단은 수신 동의를 철회하는 것과 다르며, 발신자가 해제를 반영하는 데 시간이 걸릴 수 있다. 따라서 광고 정리·수신 해제 자체를 새 시장의 증거로 보지는 않는다. Gmail 구독 관리.

표준 원클릭 수신 해제는 메일에 지정된 구독 목록을 대상으로 한다. 반면 Gmail 구독 관리의 발신자 단위 해제는 관련 목록 전체를 대상으로 설명된다. 화면마다 해제 단위가 같다고 가정하지 말고, 마케팅만 중단하고 거래·보안 알림을 유지할 수 있는지 확인해야 한다. 표준 기능이 없거나 서비스 설정이 필요한 경우에는 지원되는 설정 화면으로 안내한다. Google 발신자 FAQ, RFC 8058.

Google은 로그인 연결, 계정 연결, 데이터 접근 권한을 구분한다. 연결 해제와 외부 서비스 탈퇴·데이터 삭제·마케팅 동의 철회는 같은 동작이 아니다. 해당 도움말은 사용자의 관리 경로를 설명하며, 본 제품이 모든 연결을 조회·해제할 수 있는 범용 API의 존재를 입증하지 않는다. Google 계정 연결 관리.

검증할 차이는 **여러 메일 계정과 지원 서비스의 수신 설정을 함께 관리하고, 대화로 정한 중요 기준을 적용하면서 필수 메일 누락과 사용자 확인 시간을 줄이는가**다. 실제 서비스 연동으로 확인한 상태, 사용자가 등록·확인한 상태, 메일에서 발견한 흔적은 출처와 확인 시각을 구분한다.

### 4.3 카카오메일 지원 목표 추가 — 2026-09-24

카카오메일(@kakao.com)을 다음 메일과 별도 서비스 항목으로 포함한다. 카카오메일 공식 공지는 IMAP/POP3 이용 시 2단계 인증과 앱 비밀번호 사용을 안내한다. 이는 외부 연결 경로의 근거이며 실제 동기화·SMTP 발송·상용 운영 검증이 끝났다는 뜻은 아니다. 카카오메일 인증 공지.

기존 Catchy 등 경쟁사에 관한 ‘Gmail·네이버·다음 3사’ 표현은 당시 확인한 경쟁사 범위다. 우리 제품의 최신 지원 목표 4종과 구분하며, 경쟁사의 카카오메일 지원 여부는 이번에 확인하지 않았다.

### 5.2 기존 플랫폼의 경쟁 압력

Gmail의 Gemini와 Outlook의 Copilot도 메일 요약·초안 작성 등을 제공한다.

따라서 일반적인 메일 AI 기능만으로 사용자가 별도 서비스에 가입하고 메일 접근 권한까지 줄 이유를 만들기는 어렵다는 것이 이번 조사의 사업적 판단이다. 이는 시장 점유율이나 전환율을 실측한 결론은 아니다.

### 5.4 차별화 가설

다음 항목만으로는 충분한 차별성이라고 보기 어렵다.

- 여러 이메일 계정 연결
- 이메일 AI 요약·초안 작성
- 한국 메일 서비스 연결
- 멀티에이전트 구조 채택
- 광고 분류 또는 수신 해제 기능의 존재만을 차별점으로 주장하는 것

검증할 가치가 있는 가설은 **여러 계정의 불필요한 광고 수신을 줄이고, 사용자 기준으로 중요한 메일을 드러내며, 그 안의 약속을 완료까지 추적하는 것**이다.

예를 들면 견적 답변, 자료 제출, 납기 약속 등에서 누가 무엇을 언제까지 해야 하는지와 아직 끝나지 않은 일을 사용자가 놓치지 않도록 돕는 것이다. 이는 경쟁사가 못한다고 확인된 기능이 아니므로 같은 업무로 비교해야 한다.

경쟁 비교에서 볼 지표의 예시는 다음과 같다.

- 실제로 놓친 업무의 비율
- 잘못된 알림과 불필요한 확인 요청
- 사용자가 직접 확인하고 수정하는 시간
- 연결·동기화 실패와 복구에 드는 부담
- 고객당 모델·인프라·지원 비용
- 실제 결제와 지속 사용 여부
- 중요한 메일이 광고함에 잘못 분류되거나 수신 중단되는 빈도
- 마케팅 해제 지원 범위, 처리 결과 확인률, 사용자 수동 설정에 드는 시간
- 실제 서비스 연동 성공률과 확인 가능한 필드의 범위

멀티에이전트는 위 결과를 개선하기 위한 구현 수단으로 평가한다. 특정 구조를 채택했다는 사실만으로 더 정확하거나 저렴하다고 가정하지 않는다.

### 6.1 메일 제공사 정책과 연결 조건

### 6.2 기업용에서 구체화할 사항

직원 한 명이 계정을 연결했다는 사실만으로 회사 자료를 외부 AI에 보내도 된다고 가정해서는 안 된다.

- 회사와 서비스 제공자의 개인정보 처리 역할
- 허용한 업무와 데이터 접근 범위
- LLM 제공사에 대한 위탁·재위탁 및 국외 이전 구조
- 직원 퇴사·권한 변경 시 접근 회수
- 계약 종료 시 데이터 반환·삭제

출시 전에는 구체적인 기능과 데이터 흐름을 바탕으로 변호사·변리사의 개별 검토가 필요하다. 이번 자료는 그 검토에 앞선 쟁점 정리다.

### 다음 조사에서 답할 질문

1. 초기 고객이 사용하는 메일 계정·서비스 조합과 중요한 메일의 기준은 무엇인가?
2. 광고 분류·수신 해제와 업무 추적 중 어떤 경험이 첫 사용·재방문·결제를 만드는가?
3. 초기 설정에 어느 정도 시간이 들며, 사용자 확인과 자동 조회를 어떻게 나눠야 하는가?
4. 우선 연동할 실제 서비스는 무엇이며, 가입 상태·마케팅 수신·로그인 연결 중 어떤 정보와 변경 권한을 제공하는가?
5. 마케팅만 중단하고 주문·결제·보안 안내를 유지할 수 있는 서비스·구독 범위는 어디까지인가?
6. 대화로 만든 규칙이 중요 메일을 놓치지 않으면서 검토 시간을 줄이는가?
7. 4종 메일의 연결·동기화·발송 품질, 데이터 처리 조건, 사용자당 비용이 공개 출시 기준을 충족하는가?
8. 기존 대안 대비 사용자가 체감하는 차이와 실제 유료 유지가 있는가?

인터뷰와 소수의 사용 실험은 다음 단계의 제안이며 실행된 상태는 아니다. 기존 법률·공급사 정책·가격은 출시 판단 전에 해당 구현과 시점에 맞게 다시 확인한다.

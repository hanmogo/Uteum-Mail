2026-10-29 후속 결정 1.11의 추천안 승인으로 위 비교·경계·적용 순서는 채택 기준이 됐다. 실제 탐지기·필드별 처리·표식 수명·실패 분기·숫자 합격선이 추천안에 특정돼 있지는 않았으므로 그 값과 검증 후 운영 기능만 후속 선택으로 남긴다. 비교 계획의 승인과 실측 통과·보호 기능 제공은 구분한다.

검증은 합성 자료부터 시작한다. 실제 메일의 원문 기준선을 외부 모델에 보내는 실험에도 해당 전송의 처리 조건이 필요하다. 마스킹한 자료만 전송 가능한 경우에는 원문 비교군을 같은 외부 API로 보내지 않고 합성 자료 비교와 허용된 실자료 평가를 분리한다.

마스킹 위치는 **우리 서버 이후의 외부 전송을 줄이는 비교안**이다. 우리 서버의 원문 수집까지 없애는 구조는 아니다. 기본 메일 처리 허용 여부를 모르면 수집 대기, 외부 AI 허용만 모르면 메일 조회라는 기존 분기를 유지한다. 가명정보도 개인정보에 포함되므로 마스킹을 처리 근거·회사 권한·위탁 계약·국외 이전 검토를 생략할 사유로 삼지 않는다. ## 2. 성능 저하의 근거와 해석

| 근거 | 관찰 결과 | 적용할 때의 한계 |

서로 다른 점수를 평균 내어 마스킹의 단일 손실률을 만들지 않는다. 연구가 뒷받침하는 방향은 **작업과 모델에 따라 영향이 다르며, 원래 값을 복원하는 것만으로 이미 잃은 관계·추론을 모두 되찾을 수는 없다**는 것이다.

성능 저하는 세 가지로 나눠 조사한다. 첫째는 업무에 필요한 사실을 가린 손실, 둘째는 탐지기가 잘못된 구간을 가리거나 놓친 오류, 셋째는 대체 표시의 연결·복원 오류다. 이름이 같다고 같은 사람으로 합치거나, 같은 사람의 서명과 발신자 표시를 다른 사람으로 나누면 업무 연결과 초안이 틀릴 수 있다.

## 3. 첫 비교의 대상과 기능별 처리

### 3.1 항목별 비교안

다음은 평가 입력을 준비하기 위한 추천 정책이다. 항목별 실제 허용·제외 범위는 구현 전에 선택한다. 처리 근거가 필요한 주민번호·민감정보를 서버에 먼저 모은 뒤 가리는 것만으로 수집 문제가 해결되지는 않는다.

| 항목 | 비교할 처리 | 확인할 손실 또는 위험 |
| --- | --- | --- |
| 이메일·전화번호·상세 주소 | 실제 값이 필요 없는 작업에서는 유형과 번호가 있는 표식으로 대체 | 연락·배송·계정 지정 요청에서 대상이나 주소가 잘못 복원되는지 |
| 이름·회사명 | 같은 허용 문맥에서 같은 대상은 같은 표식, 다른 대상은 다른 표식 사용 | 동명이인, 약칭, 한영 표기, 회사 소속 변경, 발신자와 본문 인물의 혼동 |
| 주민번호·비밀번호·인증번호·결제 인증정보 | 발견한 고위험 값은 외부 입력에서 제외하는 안을 우선 비교. 생성 결과에 자동 복원하지 않음 | 탐지 누락, 구분자·공백·이미지로 표현된 값, 번호 삭제로 인한 업무 오판 |
| 날짜·금액·업무 조건 | 해당 기능에 필요한 경우 유지하고 불필요한 세부사항은 생략 | 기한·시간대·금액·조건 변경. 개인정보 외 회사 기밀과 문맥 식별 위험도 별도 고려 |
| 발신자 관계·사용자 규칙 | 서버에서 이미 확인한 규칙을 적용하고 필요한 최소 신호만 제공 | 관계를 모델이 추정해 만들어내지 않는지, 잘못된 규칙이 중요도를 바꾸는지 |
| 첨부·인용문·서명·헤더·URL | 외부로 나가는 전체 입력에 같은 정책 적용. 검사하지 못한 부분은 전송하지 않는 안을 비교 | URL 질의값·파일명·숨은 HTML·OCR 결과·첨부 원본으로 우회 노출되는지 |

예를 들어 가상 문장 ‘김민수가 이지연에게 승인을 요청했고, 이지연은 금요일까지 답변하기로 했다’는 ‘[담당자1]이 [담당자2]에게 승인을 요청했고, [담당자2]는 금요일까지 답변하기로 했다’로 바꾼다. 모두를 `[이름]`으로 바꾸는 방식은 요청자와 답변자를 구분할 수 없어 주 비교안으로 삼지 않는다. 필요하면 손실 원인을 확인하는 보조 비교로만 사용한다.

### 3.2 기능별 예상과 검증 순서

| 기능 | 예상되는 영향 | 먼저 확인할 설계 |
| --- | --- | --- |
| A1 메일 유형·답장 필요 여부 | 연락처의 실제 값은 대체해도 요청·행동 문장을 유지하면 손실을 제한할 가능성 | 유형과 중요도를 별도로 채점. 중요한 요청을 광고로 잘못 보내는 사례 포함 |

| A3 서비스·수신 관리 | 도메인·서비스명·링크를 가리면 대상 선택이 달라질 수 있음 | 서버가 확인한 서비스 ID와 제한된 후보 사용. 실제 해제 URL은 모델 생성값으로 실행하지 않음 |
| A4 답장 초안 | 호칭·관계·계약 조건이 부족하면 품질 저하 | 표식을 보존한 생성 후 허용된 값만 복원하고 사람이 사실·어조를 확인 |
| A0 자연어 요청 | ‘김 대리 메일’ 같은 대상 지정이 모호해질 수 있음 | 사용자 질의와 후보 문맥의 표식을 맞추고 실제 대상은 서버에서 확인 |

위 영향은 설계상 예상이다. 모델 적용은 최신 기획의 Luna·Sol 기준선·GPT Decisions 우선 검증·Jev 비교 후보 방향을 따르며, 마스킹 효과를 측정하는 동안 모델을 동시에 교체하지 않는다.

## 4. 평가할 처리 흐름

**추천 구조:** 권한·분석 제외 확인 → 필요한 문맥 선택 → 우리 시스템 안에서 탐지·대체 → 최종 외부 입력 검사 → 외부 모델 → 출력·표식 검사 → 허용된 값 복원 → 결과 반영 전 최신 권한 확인.

원문과 대응표는 외부 AI에 보내지 않는다. 대응표는 보호 저장소에서 암호화·접근 제한하고 일반 로그에서 제외하는 안을 비교 구현의 전제로 둔다. 외부 API로 원문을 보내 마스킹부터 시키는 방식은 이번 보호 목적에 맞지 않는다. Spring의 권한·실행 책임과 Python의 AI 처리 책임은 유지하고, 구체적인 모듈 배치는 구현 전에 선택한다.

비교 구현에는 다음 동작을 함께 검증하도록 제안한다.

- 선택한 대화와 관련 후보에서 표식을 일관되게 사용하되, 무관한 사용자·계정 사이에서 대응표를 공유하지 않는다. 계정 간 참조도 기존 허용 범위를 따르며, 필요한 문맥보다 넓은 외부 추적 식별자를 만들지 않는다.
- 원문에 우연히 등장한 `[담당자1]` 같은 문자열과 시스템이 만든 표식을 구분한다. 외부 출력의 임의 표식을 대응표 조회 권한으로 사용하지 않는다.
- 복원할 표식은 해당 작업에서 허용한 목록·유형·버전으로 검사한다. 다른 사용자의 값, 미등록 표식, 오래된 대응표를 추측하여 복원하지 않는다. 실제 발송 계정·수신 주소는 서버의 원본 식별 정보로 확정한다.
- 마스킹 실패·시간 초과·모델 재검토 때 원문을 자동 재전송하지 않는다. 같은 보호 수준으로 재시도·상위 모델 재검토하거나 해당 분석을 보류하는 대안을 비교한다.
- 프롬프트 본문뿐 아니라 도구 인자·사용자 질의·검색용 임베딩 요청·외부 로그와 추적·재시도·평가 채점 경로도 점검한다. 평가를 위해 원문을 외부 채점 모델에 보내는 행위도 별도 전송이다.
- 긴 메일의 분할 경계·한글 조사·메일 주소의 변형·인용과 서명·HTML·첨부에서 값이 일부만 남는지 검사한다. OCR 텍스트만 가리고 원본 이미지를 외부 모델로 보내지 않는다.
- AI 중단·동의 철회·원문 삭제 시 대응표·캐시·파생 결과에도 해당 정책을 적용한다. 보관 기간·복구 범위는 실제 정책으로 정한다.

## 5. 비교 검증 방법

### 5.1 세 비교군과 자료 구성

| 비교군 | 입력 | 확인할 질문 |
| --- | --- | --- |
| 원문 기준선 | 허용된 원문 또는 합성 원문 | 기존 기능의 정확도·노출 항목·지연·비용은 어느 수준인가 |
| 정답 마스킹 | 사람이 검수한 대상·구간·동일 인물 관계를 사용해 대체 | 탐지가 정확해도 정보를 가리는 것 자체로 어떤 손실이 생기는가 |
| 자동 마스킹 | 실제 탐지·대체·복원 파이프라인 적용 | 탐지 누락·과도한 삭제·연결·복원 오류가 얼마나 더해지는가 |

500개 대화부터 시작하되 같은 대화·템플릿 변형이 조정용과 평가용에 섞이지 않게 분리하는 안을 추천한다. 한국어·한영 혼합, 짧은 요청, 받은/보낸 메일, 긴 인용, 동명이인, 변경·취소·부분 답변, 시간대, 새 발신자, 번호와 금액의 혼동을 포함한다. 첨부·OCR은 지원 후보별로 별도 평가하고 미지원·제외 건수도 집계한다. 실제 민감한 값 대신 형식이 유사한 합성 시험값을 우선 사용한다.

세 군은 같은 자료·모델 버전·추론 설정·문맥 예산·서버 자원으로 비교한다. 평가 프롬프트와 채점 기준은 고정하고, 반복 실행이 필요한 생성 작업은 변동 폭도 보고한다. 정답 마스킹과 자동 마스킹에는 같은 항목 정책·표식 규칙을 적용해야 탐지 오류의 추가 영향을 구분할 수 있다.

마스킹과 모델 라우팅 효과를 분리한다. 먼저 고정 모델에서 세 군을 비교하고, 이후 같은 마스킹 조건에서 GPT Decisions·Jev와 Luna·Sol 기준선을 비교한다. 한쪽만 원문·추가 관계 설명·더 많은 검색 후보를 받게 하지 않는다. 복원한 최종 결과와 복원 전 외부 전송 내용을 각각 평가한다.

| 영역 | 측정할 내용 | 해석과 수용 판단 |
| --- | --- | --- |

| 업무 사실 | 담당자·금액·기한·취소·완료 상태의 정확도, 잘못 연결한 업무 | 단순 문장 유사도나 Sol과의 일치만으로 정답 판정하지 않음 |
| 답장 | 근거 없는 조건·약속, 잘못 복원한 이름·주소, 사람의 수정 시간 | 문체 점수와 사실 오류를 분리. 자동 채점은 사람 검수 보조로 사용 |

| 노출 | 유형별 탐지 누락·잘못 가린 비율, 전송 요청 중 보호 대상 값이 남은 비율 | 문자 구간·값·요청 단위의 분모를 각각 명시. 흔한 전화번호 성과가 드문 주민번호 누락을 가리지 않게 함 |

| 표식·복원 | 동일 대상 분리, 다른 대상 합침, 미등록 표식, 다른 사용자 값 복원 | 사용자가 바뀌거나 작업이 재시작되는 경우도 포함. 중대한 노출·오복원은 원인 수정 후 재검증하는 안을 추천 |
| 서비스 제공 범위 | 분석 보류·제외·실패 비율과 이유 | 어려운 메일을 제외한 뒤 성공한 건만으로 품질·지연을 높여 보이지 않음 |
| 시간·비용 | 탐지·복원·큐 대기·모델·재시도·승격을 포함한 전체 p95, 요청당·메일 1,000건당 비용 | 초안 p95 30초 등 기존 목표 유지. 실패·시간 초과도 건수와 함께 보고 |

각 수치는 표본 수와 함께 보고하고, 같은 대화의 원문·마스킹 결과 차이와 표본 오차를 제시하는 안을 추천한다. 500개 대화는 초기 비교 규모다. 드문 유출의 부재나 운영 전체의 무오류를 증명하지 않는다. 개인정보 탐지 재현율과 중요 메일 재현율은 서로 다른 지표다.

### 5.3 운영 도입 판단

운영 전환은 검증 결과를 보고 사용자 선택을 받는다. 기존 품질 목표를 유지한 상태에서 **외부 노출 감소, 중요한 업무의 추가 오류, 제공 가능한 기능 범위, 전체 비용과 지연**을 함께 제시한다. 원문 기준선도 기존 목표를 못 맞췄다면 그 상태를 마스킹 도입의 합격 기준으로 사용하지 않는다.

추가 허용 손실·잔존 노출·복원 오류·보류율·비용 한도는 평가 결과를 본 뒤 유리한 수치로 정하지 않고, 평가용 자료를 열기 전에 추천안과 대안을 제시해 선택받는다. 조정 후에는 분리해 둔 평가 자료로 다시 확인한다. 법적·계약상 필수 조건을 성능 향상과 맞바꾸지 않는다.

추천하는 판단 순서는 다음과 같다.

1. 필수 처리 조건과 중대한 노출·오복원 문제를 먼저 확인한다.
2. A1·A2·A4·검색 등 기능별 품질과 제공 범위를 비교한다.
3. 같은 보호·품질 조건에서 총비용과 전체 지연이 더 낮은 안을 고른다.
4. 통과한 기능부터 제한 적용 여부를 선택하고, 악화 시 같은 보호 수준의 이전 경로 또는 분석 보류로 되돌린다. 원문 자동 전송으로 복귀하지 않는다.

## 6. 도입 이점과 추가 비용

전화번호·상세 주소·인증정보처럼 많은 메일 업무에서 실제 값이 필요하지 않은 항목은 우선 보호할 가치가 높다는 판단이다. 이름·조직·발신자 관계는 일관된 표식과 서버의 확인된 규칙으로 보완할 여지가 있다. 기한·금액·계약 조건을 가려야 하는 자료는 기능 손실이 클 수 있어 전송 범위 축소·분석 제외·내부 처리 대안을 비교한다.

비용에는 탐지와 복원 연산, 대응표·캐시의 보호·삭제, 한국어 규칙 유지, 첨부 파싱, 오탐 수정, 추가 토큰·재시도·상위 모델 재검토를 포함한다. 직접 실행하는 모델의 CPU·GPU·메모리 비용도 별도로 계산한다. 마스킹했다고 토큰 수나 비용이 반드시 줄어드는 것은 아니다. 사용자당 변동비와 별도로 개발·운영 인력의 부담도 기록한다.

이점은 외부 전달량과 식별 가능성을 줄이는 범위에서 평가한다. 우리 서버의 원문 유출, 문맥으로 남는 회사 기밀, 계약·보관 조건을 없애는 효과로 계산하지 않는다. 낮은 모델 가격만으로 탐지·복원·유지보수 비용을 회수한다고 가정하지 않는다.

## 7. 추가 고도화 후보

**발견된 누락·품질 손실·병목에 대응하는 후보부터 비교하는 원칙은 2026-10-29 승인됐다.** 아래 개별 후보의 실제 채택·순서는 평가 후 선택한다. 1단계의 세부 구현에도 도구·정책 선택이 필요하며 고도화 전체의 도입을 확정한 것은 아니다.

| 외부 임베딩 마스킹으로 검색 품질 손실이 큼 → 내부 실행 임베딩 비교 | 허용된 우리 시스템 안에서 임베딩을 만들고 생성 모델에는 가린 문맥만 전달 | 직접 실행의 자원·배포·갱신·재색인 비용. 외부 임베딩은 운영이 단순하지만 전송 전 마스킹과 질의 일관성 필요 | 한국어 검색·전체 비용·지연. 내부 벡터도 개인정보와 복원 위험을 고려해 보호 |
| 첨부 누락 때문에 기능 제한이 큼 → 문서 구조별 탐지와 OCR 확대 | 스캔·표·인용·서명·파일명까지 보호 범위 확대 | 파일별 파서·OCR 비용과 오인식, 원본 첨부·이미지의 우회 전송 관리 | 파일 종류별 누락·과도한 삭제·내용 보존·보류율. 미지원 파일의 처리 선택 |
| 같은 문맥의 반복 탐지 비용이 큼 → 사용자별 결과 캐시 | 원문이 바뀌지 않은 경우 반복 연산 감소 가능 | 저장·삭제·무효화 복잡성. 사용자 간 공유 금지, 원문·정책·탐지기 버전 변경과 철회 때 재사용 중단 필요 | 적중률을 실측하고 순절감 비용·p95·오래된 결과 재사용 오류 비교 |
| 문맥상 이름 누락·오탐이 남음 → 우리 시스템 안의 소형 모델 추가 | 규칙과 개체 탐지의 어려운 문맥 보완 가능 | 상시 LLM 처리보다 어려운 사례만 추가 처리하는 안을 우선 비교. 지연·메모리·학습 자료의 권한·모델 관리 비용 증가 | 기본안 대비 누락·오탐 감소와 최종 업무 품질. 실제 고객 자료의 학습 사용은 별도 결정 |
| 직접 값은 가렸지만 신원 추정이 가능함 → 재식별 공격을 포함한 오프라인 평가 | 직책·사건·거래 내용의 조합 위험과 불필요한 과잉 삭제를 함께 발견 | 외부 공격·채점 모델로 원문을 보내지 않는 평가 환경 필요. 반복 평가 비용과 공격자의 지식에 따라 결과가 달라짐 | 합성·사용 허용 자료에서 재식별과 업무 품질을 함께 비교. 전송 요청마다 반복 LLM 호출하는 운영 구조는 별도 선택 |

개인정보 보호와 작업 유용성을 함께 평가하는 연구로 [RUPTA](https://aclanthology.org/2025.acl-long.1404/)가 있으며, 반복적인 LLM 처리 비용 때문에 작은 모델로의 이전도 다룬다. [2026년 RLAA 연구](https://aclanthology.org/2026.findings-acl.274/)는 내부 실행 환경에서 재식별 추론을 검토하고 과도한 삭제를 줄이는 방식을 제안한다. 이 연구들은 고도화의 비교 근거이며 한국어 메일에 대한 검증 결과나 해당 다중 모델 구조의 도입 결정은 아니다.

### 7.3 요구가 생겼을 때 별도 검토할 구조

**사용자 기기에서 먼저 처리하는 방식**은 우리 서버로 원문을 보내는 것부터 제한해야 하는 수요가 있을 때 비교한다. 현재 웹 서비스의 지속적 동기화·백그라운드 업무 추적과 양립하는지, 기기 종료·여러 기기·모바일 배터리·배포·업데이트를 검토해야 한다. 브라우저에서 처리한다는 이유만으로 서버와 외부 제공사에 원문이 남지 않는다고 가정하지 않는다. 현재 서버 중심 방향을 변경하는 결정은 아니다.

고객별 전용 환경이나 내부 모델만으로 분석하는 방식도 기업 수요·계약·운영비를 근거로 별도 비교할 수 있다. 개인 구독 서비스의 기본 조건으로 요구하거나 기업용 ZDR 구매와 묶어 확정하지 않는다.

## 8. 다음 결정과 산출물

**다음 결정 시점은 실제 마스킹 평가를 준비할 때다.** 첫 탐지 후보와 항목 정책, 표식·대응표의 범위, 실패 동작, 추가 수용 기준을 구체적인 비교안으로 질문한다. 지금 도구를 설치하거나 실제 고객 메일을 수집할 필요는 없다. 남은 선택은 [후속 결정 목록 1.11](10-후속-결정-목록-v1.0.md#111-마스킹-검증과-운영-적용의-세부-조건)에서 관리한다.

평가 후에는 다음 자료를 남기도록 제안한다.

- 고정한 모델·탐지기·정책 버전, 자료의 사용 조건, 조정용·평가용 분리와 정답 기준.
- 원문·정답 마스킹·자동 마스킹의 기능별 차이와 표본 수, 직접 식별정보 잔존·문맥 위험·분석 보류 비율.
- 개인정보를 불필요하게 복사하지 않은 오류 유형별 사례와 수정 전후 결과.
- 탐지·복원·검색·생성·승격·재시도까지 포함한 비용과 전체 지연, 운영 인력 부담.
- 적용할 기능·자료 범위, 적용하지 않을 범위와 이유, 남은 위험, 중단·복귀 조건 및 사용자 선택.

문서의 정책·고도화 후보를 구현 완료나 시험 통과로 표시하지 않는다. 실제 적용이 결정되면 기획서·개인정보 안내·모델 입력 계약을 같은 범위로 갱신하고 후속 결정 목록에서는 완료된 선택을 제거한다.

## 1. 초기 구현과 운영 전에 결정할 항목

한 번에 모든 답을 요구하지 않는다. 아래에는 남은 세부 선택만 기록하며, 실제 서버·AI 연결과 사용자 베타에 필요한 항목을 해당 시점에 질문한다. 화면의 가상 체험에 필요한 기준은 관련 프로토타입 문서를 따른다.

### 1.2 외부 배포용 DB 호스팅과 운영 예산

- **추천안:** 간헐적인 공유 개발·데모는 Neon을 첫 비교 후보로 제안한다. 실제 사용자 베타는 승인된 복구 목표와 월비용을 충족하는 요금제를 별도로 고른다. 제품 차이·가격·지역·복구 조건은 [비용 검토 4.5](08-Java-버전과-AWS-비용-검토-v1.0.md#45-neon과-supabase의-차이와-초기-선택안)에 정리한다.
- **대안:** 서울 앱·DB 배치가 중요하거나 통합 백엔드 기능을 활용할 경우 Supabase 서울을 우선 비교한다. 무료 한도·복구 기능이 맞지 않으면 유료 관리형 또는 기존 VM의 직접 운영을 비교하며 백업·패치·장애 대응 시간도 계산한다.
- **확인:** 전체 인프라 월 상한과 DB 몫, PostgreSQL 18.x·확장 지원, 계정·메일 저장량, 연산·전송량, 접속 지연, 실제 복원 범위. 주기적 작업이 Neon의 휴면을 막는지와 Supabase PITR 추가 비용을 포함한다. 임베딩 미도입 단계와 도입 이후 용량은 나눠 계산한다.
- **결정할 질문:** 외부 배포에 사용할 DB 호스팅 방식·사업자·지역·요금제와 월 예산을 무엇으로 정할지?
- **결정 시점:** 공유 데모·베타 등 외부 배포용 DB가 필요해질 때. [외부 호스팅 대안과 비용 계산](08-Java-버전과-AWS-비용-검토-v1.0.md)

### 1.3 작업 전달과 복구의 세부 계약

- **남은 선택:** 작업별 숨김 시간·연장 주기·호출 및 큐 재시도 횟수·실패 큐 전환 값·결과 만료 시간, 서비스 인증 수단, 메시지·결과 버전, outbox 재발행 조건과 수동 재처리 권한.
- **추천안:** 동기화·판단·초안 등 작업별 처리 시간과 실패 재현 결과를 바탕으로 수치 후보를 제시하고, 실제 배포 환경에서 지원하는 내부 인증과 호환 가능한 첫 계약 버전을 정한다. 현재 처리 시간·제공사 제한·배포 후보가 미확인이라 숫자를 임의로 확정하지 않는다.
- **대안·영향:** 긴 제한·많은 재시도는 일시 장애를 버티지만 지연·중복 호출 비용이 늘고, 짧은 제한은 실패·보류가 늘 수 있다. 인증 제품·버전 변경은 배포·키 관리·호환성 부담을 함께 비교한다.
- **결정할 질문:** 실측 후보 중 어떤 시간·횟수·예산을 쓸지, 인증·계약 버전과 수동 재처리 범위를 어떻게 정할지?
- **결정 시점:** 영구 작업 처리 구현 전. 구현 원칙은 [스택 보고서 9.4](06-기술-스택-선택-비교-보고서-v1.0.md#94-작업배포보관복구의-채택-기준)를 따른다.

### 1.4 VM 사업자와 자원 배치 및 담당자

- **남은 선택:** VM 사업자·리전·개수·인스턴스 크기, 프로세스별 자원 값과 배포·장애·호환성·DB 복구 담당자의 실제 지정.
- **추천안:** 공유 데모는 관리형 DB와 앱 VM 1개의 견적·부하를 첫 비교 기준으로 제안한다. Spring·AI의 프로세스별 자원 제한을 적용한 결과로 크기와 베타의 분리 필요성을 판단한다. 실제 자원 값·사업자는 아직 제시할 측정 근거가 없다.
- **대안·영향:** 처음부터 여러 VM에 배치하면 서버 장애 영향과 자원 경합을 줄이는 대신 고정비·배포·관찰 요소가 늘어난다. 작은 VM 1개가 충분하다는 보장은 없다.
- **확인:** 선택할 DB 지역의 왕복 지연·전송 비용, 최소 자원·전체 월비용과 각 담당자가 맡을 운영 범위.
- **결정할 질문:** VM 사업자·자원·프로세스 배치와 각 영역의 주담당을 누구로 정할지?
- **결정 시점:** 공유 배포 환경을 만들기 전.

### 1.6 첨부·관찰 데이터의 보관·수집 설정과 비용 한도

- **남은 선택:** 첨부 원본·버전·삭제 유예의 실제 기간, 로그·추적 보관 일수·수집률·추적 저장 대상, 경보 수신자와 월비용 상한.
- **추천안:** 자료 종류별 필요한 보관 근거·장애 조사 기간·예상 저장량을 확인해 기간 후보와 비용표를 제시한다. 추적은 필요한 구간의 표본 수집 후보부터 비교하고 오류 조사에 충분한지 시험한다.
- **대안·영향:** 긴 보관·높은 추적률은 조사 범위를 넓히지만 민감정보 보관량·저장·조회 비용이 늘어난다. 짧은 보관·낮은 수집률은 드문 장애의 근거를 놓칠 수 있다.
- **확인:** 첨부·사용자 삭제 안내와 저장소의 실제 만료 일치, 작업 ID 연결, OpenTelemetry 저장 후보의 접근·수집·과금 조건. 채택 원칙은 [스택 보고서 9.4](06-기술-스택-선택-비교-보고서-v1.0.md#94-작업배포보관복구의-채택-기준)를 따른다.
- **결정할 질문:** 첨부·로그·추적의 보관·삭제 기간, 추적 수집률·경보 수신 대상·저장 대상과 비용 한도를 어떻게 정할지?
- **결정 시점:** 외부 저장·관찰 서비스를 구성하기 전.

### 1.7 백업 구현과 복구 검증 범위

- **남은 선택:** 호스팅별 백업·시점 복구 요금제, 실제 주기·보관 위치·권한·경보·담당자, 첨부·외부 발송 기록과의 복구 범위, 삭제 자료의 백업 만료, 가용성 측정 경로·실패 정의·계획 점검 처리.
- **추천안:** 1.2의 후보별 견적에 DB·첨부·작업·발송 기록 복원 절차를 붙여 비용·예상 중단·실제 복원 결과로 선택한다. 가용성은 자체 메일 API의 사용자 경로를 측정 후보로 제시하고 AI·외부 제공사 지표와 나눈다.
- **대안·영향:** 개발용 덤프만 유지하면 비용·구성이 단순하지만 승인된 베타 RPO를 충족한다고 볼 수 없다. 관리형 시점 복구·다른 호스팅·직접 운영은 복구 기능과 운영 노동의 총비용을 비교한다. 관리형 DB에서 임의의 연속 WAL 보관이 가능한지는 별도 확인한다.
- **확인:** 실제 손실 시간·복원 후 서비스 재개 시간, S3 첨부 복원, 외부 발송의 중복 재실행 방지, 운영자 접근·실패 통보·삭제 만료 근거.
- **결정할 질문:** 호스팅에 맞는 백업 방식과 DB·첨부·발송 기록의 복구·측정 범위를 어떻게 정할지?

### 1.10 홈 캘린더의 세부 표시와 날짜 선택 동작

- **남은 선택:** 날짜를 선택했을 때 열 상세 목록의 배치와 표시 필드.
- **추천안:** 달력 아래에 선택한 날짜의 확정 일정·기한을 제목·시각 중심의 간단한 목록으로 표시하고, 항목을 누르면 기존 상세·원문으로 이동하는 안을 제안한다. 오늘 받은 메일 목록과 구분하면 선택 날짜를 바꿀 때 혼동을 줄일 수 있다.
- **대안·영향:** 데스크톱 보조 패널은 달력을 유지하지만 좁은 화면에서 전환이 필요하다. 별도 상세 페이지는 정보 공간이 넓지만 왕복 탐색이 늘어난다.
- **확인:** 일정 없음·시각 없는 기한·미연동 상태, 모바일 배치와 키보드 이동. 외부 캘린더 지원 범위는 별도 보류 항목이며 이 선택으로 확대하지 않는다.
- **결정할 질문:** 날짜 선택 결과를 달력 아래의 간단한 목록으로 볼지, 보조 패널이나 별도 페이지로 볼지?
- **결정 시점:** 실제 프로젝트의 홈 캘린더 구현 전. [UX·UI 문서의 메인 홈 기준](17-사용자-UX-UI-설계와-요구사항-v1.0.md#32-메인-홈--ux03)

- **추천안:** 웹의 반복 사용·동기화 신뢰성·비용·모바일 기능 수요를 확인한 뒤 React Native·Expo를 첫 후보로 비교한다.
- **대안:** Flutter 또는 Swift/Kotlin. 웹과의 코드 공유 범위·OS 기능·클라이언트 유지보수 부담을 비교한다.
- **확인:** 메일 목록·본문·편집, 첨부·푸시·캘린더 연동의 실제 기기 시험과 플랫폼별 사용자 수요.
- **결정 시점:** 웹 결과를 바탕으로 앱 검토를 재개할 때. 현재 선택은 보류 상태다.

### 3.2 인프라 고도화의 도입 범위와 시점

세부 결정은 보류한다. 초기 PostgreSQL 호스팅의 유료 확장 또는 RDS 이전, ECS/Fargate·Multi-AZ·자동 확장·별도 검색 서비스 등의 도입 여부·범위·시점은 프로토타입 이후 실제 병목·복구 요구·비용을 확인한 뒤 결정한다. DB 이전 시 허용할 중단 시간과 복구 절차도 함께 선택한다. 항목별 추천안·대안·재검토 조건은 [인프라 고도화 계획](09-인프라-고도화-계획-v1.0.md)을 따른다.

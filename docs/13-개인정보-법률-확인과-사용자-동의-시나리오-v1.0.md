# 개인정보 법률 확인과 사용자 동의 시나리오 v1.0

- 작성일과 법령 확인일: 2026-10-03
- 대상: Uteum-Mail 운영자와 화면·서버 개발 담당자. 국내 개인 가입형 메일 통합·AI 서비스 기준
- 문서 상태: 사용자 확정 정책과 법률·계약 검토 항목을 모은 실행 문서. 동의 문안과 화면 배치는 검토용 초안이며 출시용 확정 약관이 아님
- 관련 문서: [웹앱 기획서](07-웹앱-기획서-v1.6.md), [사용자 시나리오](05-전체-사용자-시나리오-v1.0.md), [Jev와 외부 AI 개인정보 검토](11-Jev와-외부-AI-개인정보-검토-v1.0.md), [후속 결정 목록](10-후속-결정-목록-v1.0.md)

**이 문서는 운영자가 무엇을 확인해야 하는지, 어느 범위의 메일 처리를 제공할 수 있는지, 이용자에게 무엇을 알리고 선택하게 할지를 연결한다.** 개인이 자신의 계정을 연결하는 서비스 형태 자체를 포기해야 한다는 판단은 아니다. 다만 계정 접근 허용, 메일 속 다른 사람의 정보 처리, 회사 자료의 이용 권한, 외부 업체 전송은 각각 근거를 확인해야 한다.

운영자는 2장의 할 일과 3장의 검토 요청문부터 확인한다. 화면 담당자는 4~6장의 동의 항목·문안·시나리오를 사용하고, 개발 담당자는 7~8장의 중단·철회·삭제와 검증 기준을 함께 적용한다. `{중괄호}`는 실제 계약·정책으로 채워야 하는 값이다. 빈칸이 남은 문안을 실제 이용자에게 게시하지 않는다.

## 1. 현재 판단과 확정 정책

### 1.1 법률 판단의 범위

**일반 검토 판단:** 개인 가입형 통합 메일·AI 서비스는 적법하게 운영할 수 있는 구조를 검토할 수 있다. 개인정보보호법은 수집·이용의 근거와 위탁·국외 이전 조건을 규정한다. Google도 외부 메일 클라이언트와 생산성 목적의 생성형 AI 요약을 허용 사례로 제시한다. 이 사실만으로 우리 서비스의 실제 계약·자료 처리까지 승인된 것은 아니다. [개인정보보호법 제15조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0015&lsiSeq=283839&urlMode=lsScJoRltInfoR), [Google Workspace 정책](https://developers.google.com/workspace/workspace-api-user-data-developer-policy)

다음 표현은 출시 판단이나 사용자 안내에 사용하지 않는다.

| 피할 표현 | 이 문서의 판단 |
| --- | --- |
| 본인이 연결했으므로 메일 속 모든 정보를 처리해도 된다 | 계정 소유자와 메일 속 고객·거래처는 다른 정보주체일 수 있음. 처리 역할과 근거를 검토해야 함 |
| 회사 규정 위반은 전부 직원 책임이다 | 직원의 사규 위반만으로 우리 서비스가 자동 위법이 되는 것은 아니지만, 우리 자신의 개인정보 처리 의무를 없애지는 못함 |
| 공식 API로 연결되면 모든 이용이 합법이다 | 접근 허용과 이후 사용·보관·외부 전달의 조건은 따로 확인 |
| 필터가 비밀 메일을 전부 막아 준다 | 탐지·마스킹에는 누락 가능성이 있음. 우리 서버에 들어오는 단계와 외부 AI로 나가는 단계를 구분 |
| 학습에 쓰지 않으므로 저장도 하지 않는다 | 학습 제한·요청 보관·로그·백업·지원 자료의 조건을 별도로 확인 |
| 기업용 ZDR이면 법률 검토가 끝난다 | ZDR은 공급자의 보관 조건에 관한 항목. 처리 권한·법적 근거·우리 서버의 보관까지 대신하지 않음 |

위탁받은 서비스에도 개인정보보호법상 의무가 적용될 수 있다. 제3자의 정보통신망 접근 권한은 제공사가 부여한 범위도 고려한다. 따라서 ‘개인 가입’이나 ‘사용자 허락’만으로 모든 책임을 정리하지 않는다. [제26조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0026&lsiSeq=283839&urlMode=lsScJoRltInfoR), [대법원 2021도1533 판결](https://file.scourt.go.kr/dcboard/1727143941880_111221.pdf)

### 1.2 사용자 확정 사항과 미정 사항

| 구분 | 내용 |
| --- | --- |
| 확정 | 가입의 약관 동의와 개인정보 처리방침 공개를 구분. 필요한 별도 동의는 해당 행위 전에 받음 |
| 확정 | 앱의 메일 처리 안내 → 제공사 인증 → 시작 설정·선택 → 메일 수집과 허용된 분석 순서 |

| 확정 | 기본 메일 처리는 허용되고 외부 AI 허용만 모르면 메일 조회만 제공 |
| 확정 | 기본 메일 처리도 허용 여부를 모르면 해당 계정의 수집 대기. 가상 체험·다른 허용 계정은 이용 가능 |
| 확정 | 최근 30일은 초기 과거 분석의 기본 제안. 새 메일 자동 분석과 보관 기간은 별도 표시 |
| 확정 | AI 기능 중단과 데이터 삭제의 효과를 구분. 개인정보 동의 철회에 따른 법적 조치는 7장에 별도로 설명 |
| 미정 | 사용자 진술에 의존할 수 있는 조건, 회사의 권한을 확인할 근거·문구, 자료별 처리 근거와 국외 이전 방식 |
| 미정 | 실제 업체·처리 국가·보유 및 삭제 기간, 새 메일 자동 분석 기본값, 업무용 추가 보호의 범위 |
| 문안 제안 | 아래의 정확한 문구·체크박스 배치·재진입 화면. 법률 검토와 실제 계약을 반영한 뒤 확정 |

업무용 수집 대기 분기는 **우리가 선택한 보수적인 운영 정책**이다. 법이 모든 메일 서비스에 동일한 화면을 요구한다고 확인한 것은 아니다. 이 문서 작성만으로 추가 출시 범위·연령 정책·기업용 계약 구매를 확정하지 않는다.

## 2. 운영자가 직접 해야 할 일

### 2.1 진행 순서와 완료 자료

아래 순서는 출시 준비를 위한 추천이다. 변호사 사전검토는 위험을 줄이기 위한 권장 절차이며, 이 사업에 일률적인 ‘변호사 승인서’가 법정 필수라는 뜻은 아니다. 개발 중에는 가상 메일로 화면과 처리 흐름을 검증할 수 있다.

| 순서 | 운영자가 할 일 | 받아 두거나 결정할 자료 | 시점 |
| --- | --- | --- | --- |
| 1 | 개인정보 분야 변호사에게 3.2의 범위를 검토 의뢰 | 개인용·업무용·타인 정보의 처리 근거, 회사 계약 필요 여부와 개인 진술의 허용 조건, 제공 가능한 범위를 적은 검토 결과 | 큰 개발비 투입 전에 구조 검토 권장. 실메일 수집 전에는 적용 근거 확인 |
| 2 | 사용할 메일 연결 방식과 AI·임베딩·호스팅 업체를 실제 계정 기준으로 확인 | 계약 주체, API 경로, 실제 처리업체와 국가, 개인정보 항목·용도·로그·백업 흐름 | 실제 서비스 계정 구성과 자료 전송 전 |
| 3 | 우리에게 적용되는 계약을 체결·확인 | DPA 등 위탁 관련 계약, 표준 약관 수락 기록 또는 주문서, 재위탁 조건, 학습·보관·사고·삭제 조항 | 해당 업체에 실메일을 보내기 전 |
| 4 | 공급자의 공개 자료로 확인되지 않은 항목을 요청 | 계정별 설정, ZDR 적용 범위·예외·가격, 최대 보관·삭제 기한, 보안 보고서 원문과 적용 범위 | 공급자 선정·계약 판단 시 |
| 5 | 우리 서비스의 수집·보관·삭제 기준을 결정 | 자료별 목적·근거·기간·삭제 방법, 백업·파생 자료·독립 업무의 처리, 중단과 철회 경로 | 실제 사용자 베타 전 |
| 6 | 제공사 심사·상용 운영 조건을 확인하고 필요한 절차 진행 | Gmail 범위별 검증·보안 평가의 적용 여부와 결과, 다른 제공사의 실제 연결·자동화·상용 이용 조건 | 제공사 요구에 따른 외부 사용자 연결 전 |
| 7 | 이용자 안내와 연락 창구를 확정·공개 | 운영 주체·문의처, 약관·처리방침, 실제 필요한 동의 문안, 수탁자·국외 이전 안내, 권리 행사·사고 대응 담당 | 실제 사용자에게 해당 처리를 제안하기 전 |
| 8 | 개발 결과가 약속과 맞는지 확인 | 8.2의 검증 결과, 외부 업체 삭제·사고 협조 경로, 미해결 항목과 출시 가능 범위 | 실제 사용자 베타 시작 전 |

공급자가 쓰는 DPA는 개인정보 처리에 관한 계약이다. 주문서는 요금·기간·추가 조건 등을 정하는 계약 문서이며, 모든 API 이용에 별도 주문서가 존재하는 것은 아니다. ZDR은 요청 자료의 보관 제한 조건으로 이해하되 업체별 범위가 다르다. **DPA·주문서·ZDR을 세 가지 상품처럼 모두 별도 구매해야 한다는 뜻은 아니다.** 우리 계약에 무엇이 적용되는지와 요구 조건을 충족하는지를 확인한다.

### 2.2 직접 정할 수 있는 것과 확인받아야 하는 것

| 항목 | 운영자가 정하거나 요청할 수 있는 부분 | 혼자 선언해서 확정할 수 없는 부분 |
| --- | --- | --- |
| 보관·삭제 | 우리 서비스의 보관 목표, 삭제 요청 절차, 실제 지원 조건에 맞는 약속 | 공급자 로그·백업이 실제로 언제 지워지는지 |
| 처리 국가 | 국내 리전 또는 지역 제한 옵션 선택 | 공급자의 장애 전환·지원 인력 접근·재수탁자까지 모두 그 국가에 있는지 |
| 보안 | 우리 시스템의 암호화·접근 통제·인증 정보 보호 | 공급자가 독립 감사를 통과했는지와 우리 API가 감사 범위에 포함되는지 |
| 사고 대응 | 우리 담당자·연락망·초기 대응·사용자 안내 절차 | 공급자의 실제 통지·협조·배상 의무. 법정 통지·신고 요건을 임의로 완화할 수도 없음 |
| 처리 근거 | 기능·자료 범위를 선택하고 검토에 필요한 사실 제공 | 법적 요건을 충족하지 않는 처리를 약관 동의 문구만으로 적법하게 만들기 |
| 회사 자료 | 사용자에게 허용 여부를 묻고 그 진술을 기록 | 직원 한 사람의 체크를 회사의 공식 승인으로 인정하기 |

공개 법령·정책·표준 계약은 기존 [11번 보고서](11-Jev와-외부-AI-개인정보-검토-v1.0.md)에 조사되어 있다. 운영자가 추가로 확보해야 하는 핵심은 **우리 명의 계약·계정 설정의 증빙과 실제 서비스에 적용한 법률 검토 결과**다. 공개 자료 조사만으로 그 증빙을 대신할 수 없다.

## 3. 제공할 수 있는 범위와 법률 검토 요청

### 3.1 상황별 판단

‘조건 충족 시 가능’은 해당 계정에 이미 모든 조건이 충족됐다는 판정이 아니다. 아래 제품 분기는 필요한 처리 근거·계약·제공사 조건이 갖춰진 뒤 적용한다.

| 상황 | 현재 판단 | 제공 범위 또는 확인할 일 |
| --- | --- | --- |
| 실제 정보가 없는 가상 메일 체험 | 개발·설계 검증에 사용할 수 있음 | 실제 개인정보를 복사하거나 토큰·실제 주소를 넣지 않은 자료 사용 |
| 개인용 계정의 기본 통합 조회 | 조건 충족 시 가능 | 접근 권한, 본인·타인 정보의 처리 근거, 저장·국외 이전·제공사 조건 확인 |
| 개인용 계정의 AI 분석 | 조건 충족 시 가능 | 기본 처리 조건에 더해 AI의 목적·항목·업체·지역·보관과 필요한 동의 확인 |
| 업무용이고 기본 메일·AI 처리 허용이 확인됨 | 허용 범위에서 제공하는 방향 | 회사 자료의 권한 확인 근거와 계약 관계는 별도 법률 검토. 개인의 진술 자체를 회사 승인으로 표시하지 않음 |
| 업무용이고 기본 처리는 허용, AI 허용만 미확인 | 사용자 확정 제품 정책 | 메일 조회만 제공. AI·외부 임베딩 전송 중단 상태로 시작 |
| 업무용이고 기본 처리도 허용 여부 미확인 | 사용자 확정 제품 정책 | 그 계정은 수집 대기. 본문·메일 목록을 가져오지 않고 재진입 안내 |

| 다른 계정 자료를 답장 근거로 사용 | 별도의 참조 허용 범위 안에서 제공 | 같은 사용자의 계정이라는 이유만으로 교차 사용하지 않음 |

| 건강·정치적 견해 등 민감정보 | 일반 메일 분석 동의만으로 포괄하지 않음 | 실제 정보주체에 대한 별도 근거와 보호조치 검토. 초기 지원·제외 범위는 미정 |

주민등록번호에는 제한된 법정 처리 근거가 필요하고, 민감정보에는 별도 동의나 법령상 근거 등 요건이 있다. 결제 정보 전체를 개인정보보호법상 민감정보로 일괄 분류하지는 않는다. 카드 인증값·비밀번호 등은 성격에 맞는 별도 보호·취급 제한을 확인한다. [제24조의2](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1020399435), [제23조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0023&lsiSeq=283839&urlMode=lsScJoRltInfoR)

만 14세 미만 가입을 일률적으로 차단하는 것이 법정 의무는 아니다. 해당 아동의 개인정보 처리에 법상 동의가 필요하면 법정대리인 동의와 확인 등이 필요하다. 아동 가입 지원 여부와 화면은 아직 확정하지 않았다. [제22조의2](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=02&joNo=0022&lsiSeq=283839&urlMode=lsScJoRltInfoR)

한국 사용자 중심이라는 기획을 유지하되, EU 내 사업장·EU 내 개인 대상 제공·행동 관찰 등 실제 조건에 따라 GDPR 적용을 검토한다. 유럽 국적자가 메일에 등장한다는 사실 하나만으로 적용 여부를 단정하지 않는다. 적용되는 경우 이 문서의 국내용 문안만으로 끝내지 않는다. [EU 집행위원회 적용 설명](https://commission.europa.eu/law/law-topic/data-protection/information-business-and-organisations/application-gdpr_en)

**가입 정보 안내:** `{운영 주체}`는 계정 생성·로그인을 위해 `{필요한 가입 항목}`을 `{검토된 처리 근거}`에 따라 처리합니다. 보유 기간은 `{기간 또는 구체적인 종료 기준}`입니다.

**버튼:** `가입하기` / `가상 메일로 체험하기`

별도 동의가 필요한 가입 항목이 확인되면 목적·항목·기간·거부 영향을 제시한 항목을 추가한다. ‘처리방침에 동의합니다’를 필수 체크로 추가해 모든 개인정보 처리를 포괄하지 않는다.

### 5.3 시작 설정의 용도와 업무용 권한

**화면 제목:** 이 계정의 사용 범위를 정하세요

**용도 선택:** `개인용` / `업무용` / `둘 다`

업무용 또는 둘 다를 선택하면 다음 두 질문을 표시한다. 문구는 검토용이며, 인정할 근거와 실제 사용자 진술의 범위는 법률 검토 후 확정한다.

> **메일 조회·저장:** 이 계정의 메일을 Uteum-Mail 서버로 가져와 조회·보관하는 것이 소속 조직의 정책과 본인의 권한 범위에서 허용되나요?
>
> `허용되는 것을 확인했어요` / `잘 모르겠어요`

> **외부 AI 분석:** 아래에 표시된 업체가 메일 내용을 분석하는 것도 허용되나요?
>
> `허용되는 것을 확인했어요` / `잘 모르겠어요`

**보조 안내 제안:** 허용되지 않는 계정·자료는 연결을 진행하지 말고 소속 조직의 정책을 확인해 주세요. `연결 취소` / `정책 확인 방법 보기`

‘정책 확인 방법’에는 사내 외부 앱·AI 이용 지침의 확인, 필요한 경우 권한 있는 담당자에게 문의할 내용을 안내한다. 문의할 때 **우리 서버의 조회·저장**과 **표시된 외부 AI로의 전달**을 함께 확인하도록 설명한다. 회사에 자동으로 연락하거나 회사 승인을 받았다고 표시하지 않는다.

| 응답 | 사용자에게 보여줄 문구 초안 | 처리 |
| --- | --- | --- |
| 기본 처리 허용, AI만 미확인 | “우선 메일 조회만 시작합니다. AI는 회사 정책을 확인한 뒤 설정에서 켤 수 있습니다.” | 기본 처리에 필요한 선택·동의 완료 후 동기화만 시작 |
| 기본 처리도 미확인 | “이 계정은 사용 권한 확인을 기다립니다. 아직 메일을 가져오지 않았습니다.” | 해당 계정 수집 대기. 가상 체험·다른 계정·설정 재진입 제공 |
| 둘 다 허용 확인 | “이제 분석할 범위와 AI 사용 여부를 선택해 주세요.” | 아래 선택과 실제 처리 조건 확인 후 시작 |

이 응답은 **이용자의 진술 기록**이다. 회사 승인서, 고객 개인정보에 대한 포괄 동의 또는 우리 의무의 면책으로 취급하지 않는다.

**버튼:** `AI 분석 켜고 시작` / `메일만 보기`

AI에 필요한 선택·동의가 빠졌다면 빠진 항목을 표시하고 ‘메일만 보기’로 진행할 수 있게 한다. 필수 근거가 미확인인 기본 처리까지 이 버튼으로 시작하지 않는다. 버튼을 누른 사실 하나로 두 동의가 모두 선택됐다고 저장하지 않는다.

기본 호스팅·인증 정보 저장 등이 해외에서 이뤄지면 AI 안내와 구분하여 해당 경로를 설명한다. 동의가 이전 근거이면 5.4의 국외 이전 표를 기본 처리의 실제 값으로 별도로 작성한다.

- [ ] 기본 메일 처리를 위한 위 개인정보 국외 이전에 동의합니다. — 필수·선택 표시는 실제 서비스 필요성과 법률 검토 후 확정

계약 이행에 필요한 위탁·보관 등 다른 근거가 적법하게 적용된다면 해당 공개·알림 요건으로 구성한다. **AI용 국외 이전 동의 하나가 우리 서비스의 모든 해외 처리를 포괄한다고 안내하지 않는다.**

수집·이용 동의와 구분하며, 국외 이전에도 해당하면 이전 요건을 함께 충족한다. 가입자의 동의가 메일 속 모든 사람의 제공 동의로 바뀌는 것은 아니므로 3.2의 처리 근거 검토가 선행되어야 한다. [제17조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0017&lsiSeq=283839&urlMode=lsScJoRltInfoR), [제22조](https://law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1022694673)

## 6. 사용자가 웹앱을 이용하는 시나리오

다음은 화면·서버 검증에 사용할 기대 동작이다. 구현 완료를 뜻하지 않는다. 기존 ONB-01~05의 흐름을 구체화하며, 법률 근거·계약 조건을 먼저 충족한다는 전제다.

| 상황 | 사용자에게 전달할 내용과 선택 | 서비스의 동작 |
| --- | --- | --- |
| 개인용 계정에서 AI 시작 | 가입 → 앱 내 처리 안내 → 제공사 인증 → 범위 설정 → 필요한 항목별 동의 → AI 시작 | 선택·고지 버전 기록 후 허용 범위만 수집·분석 |
| 개인용 계정에서 AI 거부 | “메일만 보기로 시작할 수 있습니다.” | 기본 처리 조건 충족 시 동기화만 시작. 외부 AI·임베딩 호출 없음 |
| 업무용에서 기본 처리 허용, AI 미확인 | “우선 메일 조회만 시작합니다.” / 정책 확인 안내 | AI 꺼짐. 나중에 켤 때 권한과 필요한 동의를 다시 확인 |

| 개인용·업무용이 함께 있는 계정 | 업무용 자료가 포함됨을 확인하고 업무용 권한 질문 표시 | 개인용으로 추정된 도메인이라는 이유로 업무용 확인을 생략하지 않음 |

| 인증 취소·시작 설정 중 이탈 | 연결 미완료 또는 시작 설정 대기 상태 표시 | 메일을 미리 가져오거나 AI 작업을 시작하지 않음. 나중에 이어서 설정 가능 |
| 최근 30일만 분석하고 새 메일 자동 분석은 끔 | 두 설정을 별도로 확인 | 초기 허용 범위만 분석. 이후 도착한 메일을 자동 분석하지 않음 |
| AI를 나중에 켬 | 당시 적용 업체·국가·범위·보관 조건을 다시 보여줌 | 필요한 권한·선택·동의 확인 후 켬. 과거 거절을 자동 동의로 바꾸지 않음 |
| AI 기능을 끔 | 중단 범위와 기존 결과 처리, 동의 철회 경로 안내 | 대기 작업 취소·새 전송 중단. 이미 전송한 요청을 회수했다고 표시하지 않음 |
| 개인정보 동의를 철회함 | 대상 처리·중단 기능·자료의 조치와 예외 사유 안내 | 7.1에 따라 필요한 파기 등 조치. 별도 삭제 요청이 없다는 이유로 방치하지 않음 |
| 계정 연결 해제·자료 삭제 | 우리 앱 자료와 원래 메일 서비스의 원본을 구분 | 새 수집 중단과 선택한 삭제, 법상 필요한 삭제를 이행. 남는 법정 보존 자료는 근거·기간 안내 |
| Jev 등 처리업체나 이전 국가 변경 | 실제 변경 내용과 필요한 재동의 제시 | 동의 기반 변경은 재동의 전 해당 변경 경로로 전송하지 않음. 거부 시 해당 기능의 실제 대안·제한 안내 |
| 민감정보·주민번호 등이 탐지됨 | 필요한 경우 “이 자료는 현재 분석 범위에서 제외되었습니다.” | 확정된 제외·보호 절차 적용. 발견 사실 자체를 불필요하게 로그에 복제하지 않음. 미탐지를 없다고 단정하지 않음 |
| 메일 속 다른 사람이 권리 행사 요청 | `{개인정보 문의처}`와 확인 절차 안내 | 실제 처리 역할과 요청 범위를 확인해 직접 조치하거나 책임 있는 주체와 협력. 가입자가 아니라는 이유로 일괄 무시하지 않음 |

기본 메일 처리의 국외 이전 동의가 필요한 계정은 AI 선택에 앞서 그 조건도 충족해야 한다. 시나리오의 ‘메일만 보기’는 외부 처리가 전혀 없다는 뜻이 아니다.

서비스 연동·캘린더·추가 계정·다른 계정 자료 참조는 실제 기능을 켜는 시점에 필요한 권한·범위를 안내한다. 가입 때 미래 기능 전체를 포괄 동의시키지 않는다. 이미 유효하게 허용된 동일 범위의 매 메일마다 재동의 팝업을 띄우는 흐름도 기본으로 두지 않는다.

## 7. 중단과 철회와 삭제 안내

### 7.1 기능 설정과 법적 권리 행사

**‘AI 기능 끄기와 삭제를 구분한다’는 기존 결정이 동의 철회 뒤 자료를 계속 보관해도 된다는 뜻은 아니다.** 법 제37조는 동의 철회 때 지체 없는 파기 등 필요한 조치와 예외·사유 통지를 정한다. 처리 목적 달성 등으로 불필요해진 개인정보의 파기 의무도 별도로 적용된다. [제37조](https://law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0037&lsiSeq=283839&urlMode=lsScJoRltInfoR), [제21조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034516739)

| 사용자의 요청 | 처리와 안내 기준 |
| --- | --- |
| 앞으로의 AI 기능만 중단 | 대기·신규 분석과 전송 중단. 기존 결과를 계속 보여주려면 해당 보관·이용 근거와 기간이 유효해야 함 |
| 개인정보 처리 동의 철회 또는 법상 처리정지 요구 | 대상 범위에 필요한 파기 등 조치를 진행. 예외로 조치하지 않는 경우 법적 사유와 남는 자료·기간을 설명 |
| 계정 연결 해제 | 새 동기화·발송 등 연결을 통한 동작 중단. 이미 저장한 자료와 인증 정보의 처리를 별도로 안내 |
| 보관 자료 삭제 | 원문 복사본·분류·요약·임베딩·캐시·관련 작업·업체 보관분·백업의 실제 삭제 절차 적용. 원래 메일 서비스 원본 삭제와 구분 |

**화면 제안:** 설정의 같은 위치에 `AI 기능 중단`, `개인정보 동의 관리`, `계정 연결 해제`, `보관 자료 삭제`를 둔다. 실제 사용자가 동의 철회나 처리정지를 요청한 경우, 이를 단순 기능 토글 변경으로 축소 해석하지 않는다. ‘동의 철회’라고 표시한 버튼이 신규 호출만 끄고 법상 필요한 후속 조치를 생략하게 만들지 않는다.

기존 결과·독립 업무의 유지 여부는 해당 자료의 근거와 사용자 선택을 함께 검토한다. 근거 없는 계속 보관을 약관 문장으로 허용하지 않는다. 삭제 완료까지의 기간은 실제 시스템·공급자 조건과 법적 요구를 대조하여 확정하며 임의의 일수를 약속하지 않는다.

### 7.2 사용자에게 보여줄 상태 문구

| 상태 | 문구 초안 |
| --- | --- |
| AI 중단 | “이 계정의 새 AI 분석을 중단했습니다. 기존 분석 결과의 보관·삭제와 동의 철회는 데이터 설정에서 확인할 수 있습니다.” — 실제 적용 근거·상태에 맞춰 사용 |
| 동의 철회 접수 | “`{처리 항목}` 동의 철회를 접수했습니다. 해당 처리를 중단하고 필요한 자료 조치를 진행합니다. `{남는 자료가 있으면 사유·기간}`” |
| 삭제 진행 | “우리 서비스에 저장된 `{삭제 범위}`를 삭제하고 있습니다. 외부 처리업체·백업의 처리 상태는 `{조회 경로}`에서 확인할 수 있습니다.” |
| 삭제 완료 | “`{실제로 삭제 완료한 범위}`의 삭제가 완료되었습니다. `{법정 보존 자료 등이 있으면 별도 명시}`. 원래 메일 서비스의 메일은 삭제하지 않았습니다.” |
| 계정 해제 | “앞으로 이 계정의 메일을 가져오거나 발송하지 않습니다. 보관 자료의 처리 상태는 `{데이터 설정}`에서 확인할 수 있습니다.” |

권리 행사 접수·본인 확인은 요청을 처리하는 데 필요한 범위로 설계한다. 일률적으로 주민등록번호나 실제 메일 전체를 추가 제출하도록 요구하는 방식을 기본으로 삼지 않는다.

### 7.3 업체 변경과 사고 안내

동의에 근거한 국외 이전에서 업체·국가·항목·목적·보유 기간 등 법정 안내 사항이 바뀌면 변경 안내와 동의 절차를 적용한다. 단순 공지 뒤 거부하지 않았다는 이유로 새 업체에 보내지 않는다. 다른 이전 근거를 사용하는 경우에는 그 근거의 유지 여부와 공개·알림·계약 절차를 따로 검토한다. [제28조의8](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=08&joNo=0028&lsiSeq=283839&urlMode=lsScJoRltInfoR)

**변경 안내 초안:**

> `{기능}`의 처리업체가 `{기존 업체}`에서 `{새 업체}`로 변경될 예정입니다. 변경되는 항목은 `{국가·자료·목적·기간 등 실제 변경}`입니다. 새 조건은 아래와 같습니다. 동의하지 않으면 `{해당 기능의 제한 또는 기존 경로 유지 가능 여부}`가 적용됩니다.

**버튼:** `새 조건에 동의` / `동의하지 않음` / `자세히 보기`

사고 대응은 운영자가 정할 연락망·절차와 법정 통지·신고 요건을 함께 반영한다. 공급자의 계약상 통지만 기다리는 구조로 정하지 않는다. 안내에는 확인된 사실, 해당 자료·이용자 범위, 진행 중인 조치, 이용자가 할 일, 문의처와 추가 안내 경로를 넣는다. 아직 확인되지 않은 유출 범위를 ‘유출 없음’으로 표시하지 않는다. 상세 법령과 공급자 통지 조건은 [11번 보고서 4.5](11-Jev와-외부-AI-개인정보-검토-v1.0.md#45-사고-통지와-삭제)를 기준으로 최신 확인한다.

## 9. 문서의 사용과 갱신 기준

이 문서는 운영자 체크리스트와 화면 초안의 기준 문서로 사용한다. 공급자별 공개 계약·보안 조사 결과는 11번 보고서에서 유지하고, 확정된 제품 정책은 7번 기획서에 반영한다. 앞으로 사용자의 선택이 필요한 항목은 10번 후속 결정 목록에만 남긴다.

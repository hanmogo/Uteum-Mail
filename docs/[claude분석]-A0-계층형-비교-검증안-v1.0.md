# [claude분석] A0 계층형 비교 검증안 v1.0

- 작성일: 2026-10-06
- 작성 주체: Claude (사용자 요청에 따른 검증안). 기존 기획·설계 문서는 수정하지 않았다.
- 상태: **비교 검증안**. 초기 모델 배분(A0 오케스트레이터 = Sol, 사용자 확정 2026-09-27)을 변경하는 결정이 아니며, [에이전트+결정모델 세부 구조 v1.0](12-에이전트+결정모델-세부-구조-v1.0.md) §11.1의 두 번째 비교안("Luna 기반 제한 라우터와 Sol 복귀")을 구체화하는 하위 검증안이다.
- 관련 문서: [상세 설계 v0.3](01-에이전트-상세-설계-v0.3.md) §3 A0·A0.1, [세부 구조 v1.0](12-에이전트+결정모델-세부-구조-v1.0.md) §2·§6.2·§10·§11, [후속 결정 목록](10-후속-결정-목록-v1.0.md) "Jev 라우팅의 비교 경로와 입출력 계약", [결정모델 적용 분석](%5Bclaude분석%5D-결정모델-적용-비용-성능-지연-분석-v1.0.md)
- 질문: A0의 기능(대화 유형 판정·구조화 추출·혼합 요청 분해·규칙 생성·직접 응답·결과 설명)을 한 모델이 한 번에 처리하는 현행 구성과, 기능별로 Luna·결정 모델·Sol을 나눠 쓰는 계층형 구성을 같은 조건에서 어떻게 비교할 것인가.

## 1. 요약

| 항목 | 내용 |
| --- | --- |
| 방향 | Sol로 기준 성능을 먼저 확보하면서, 같은 평가 세트에서 계층형 두 구성을 비교한다. A0의 기능별로 모델을 달리 쓰자는 방향은 비교 후보이지 결정이 아니다 |
| 비교 구성 | ① A0 Sol 기준선 ② Luna 통합 처리 → 필요시 Sol ③ 결정 모델 게이트 → Luna 또는 Sol |
| 핵심 측정 | Sol 승격률, **형식·권한 검사를 통과했지만 실제로 틀린 Luna 결과 비율**, Sol·확인 질문이 필요한 요청을 Luna로 통과시킨 비율, 요청 항목 누락률, 잘못된 대상 선택률, 지연 3종, 실제 사용량 기준 비용 |
| 서버 강제 사항 | 일반 Luna 경로에는 지속 규칙 저장 동작을 허용하지 않는다. 권한·대상·최신 상태 검사 실패는 보류이며 Sol 승격 대상이 아니다 |
| 비용 | 기존 가정에서 A0 월 비용은 두 분기 방식 모두 약 $0.20으로 계산되지만 조건부 추정이다. 실측으로 대체한다 |
| 진행 | 운영 몇 달을 기다리지 않고, 기준선을 고정한 뒤 격리된 평가에서 두 후보를 같은 세트로 측정해 경계를 정한다 |

## 2. 전제

### 2.1 유지하는 것

- A0 = Sol, A4 = Sol, A1·A2·A3 = Luna 기본과 조건부 Sol 재검토 (사용자 확정).
- A0.1 대화 범위 정책, 요청 항목별 판정 출력(`request_items[]`), 백엔드의 실제 지원 기능·지시 범위·권한 검사 (상세 설계 §3·§4).
- 세부 구조 §2의 세 기능 구분: **업무 경로 라우팅**(어떤 역할·순서를 쓸지), **모델 라우팅**(같은 판단에 Luna 또는 Sol), **작업 계획**(요청 분해와 의존 관계, A0의 책임). 세 기능의 비용과 오류는 따로 집계한다.
- 세부 구조 §6.2의 복귀 기준. 특히 "모델과 무관한 권한·대상·최신 상태 검사 실패 → 실행 보류 또는 재조회. 더 강한 모델의 판단으로 검사 실패를 우회하지 않음".

### 2.2 이 검증안에서 바로잡은 가정

| 이전 표현 | 바로잡은 내용 |
| --- | --- |
| 대화 유형 판정은 보기 중 선택이므로 추론이 불필요 | 출력 형식이 enum이나 yes/no여도 판단은 어려울 수 있다. "이번에는 초안만 만들고, 앞으로 이런 메일은 먼저 알려줘"는 초안과 지속 규칙이 섞인 요청이며, 게이트가 단일 초안 요청으로 분류하면 뒤의 Sol 경로에 도달하지 못한다. 게이트 오류는 상류 오류라 하류 설계로 복구되지 않는다 |
| Sol이 필요한 경우는 혼합·모호 요청과 규칙 생성 두 종류 | 초기 Sol 우선 후보일 뿐이다. 긴 대화의 지시를 이어받거나 여러 예외를 적용하는 단일 요청도 어려울 수 있고, 단순한 혼합 요청은 Luna로 충분할 수 있다. 경계는 측정으로 정한다 |
| Luna가 틀리면 백엔드가 잡는다 | 백엔드가 잡는 오류와 통과시키는 오류가 다르다(§3.3). 통과한 오류는 사람 검수로 측정해야 한다 |
| 권한 불일치 → Sol 승격 | 삭제. 대상 해석이 모호하면 Sol 재해석이 가능하지만, 실제 권한 검사 실패는 해당 동작을 보류한다 |
| 규칙 생성을 Sol에 한정하면 가장 비싼 오류가 구조적으로 차단된다 | 일반 Luna 경로에 규칙 저장 동작을 서버가 허용하지 않는 것이 핵심이며, 그래야 Luna의 일반 처리 오류가 규칙 저장으로 이어지는 경로가 끊긴다. Sol이 규칙을 잘못 만드는 가능성은 남는다 |
| 코드 구조만 계층형으로 미리 만들고 모델은 Sol로 시작 | 기능별 로그 분리와 모델 호출 분리는 다르다. 한 번의 Sol 호출을 세 번으로 나누면 기준선부터 비용이 부풀어진다. 기준선은 호출 횟수를 바꾸지 않고 로그 태그만 분리한다 |

## 3. A0 기능 분해와 비교 구성

### 3.1 A0의 기능

| 기능 | 현행(상세 설계 §3 A0) | 성격 | 초기 모델 후보 |
| --- | --- | --- | --- |
| 대화 유형 판정 (`conversation_type`, `response_mode`) | Sol | 선택형. 단, 혼합·모호 감지가 어려울 수 있음 | 결정 모델 또는 Luna. 보수적 임계값 |
| 인사·잡담 1~3문장, 범위 안내 | Sol | 짧은 생성 | Luna |
| 단일·명확한 핵심 요청의 의도·대상 구조화 | Sol | 구조화 추출 | Luna + Structured Outputs |
| 혼합 요청 분해, 모호한 요청의 확인 질문 | Sol | 작업 계획 | Sol |
| 규칙 생성 (조건·예외·계정·기간·향후 적용 구조화, 6.2) | Sol | 추론 + 높은 오류 비용 | Sol. 규칙 전용 경로 |
| 결과 설명 | Sol | 생성 | 템플릿 → Luna → 복잡하면 Sol |

모델 후보는 비교 출발점이며 확정이 아니다. 긴 대화 문맥을 이어받는 짧은 요청("그건 빼고 다시"), 여러 예외가 걸린 단일 요청("A사는 중요하지만 행사 광고는 일반으로")은 단일·명확으로 보여도 Sol이 필요할 수 있다.

### 3.2 비교 구성

같은 평가 세트·허용 사실·선택 대상·이전 대화·업무 경로 목록을 제공한다. 한쪽의 판단이나 해설을 다른 쪽 입력으로 주지 않는다(세부 구조 §11.1).

| 구성 | 호출 구조 | 확인할 질문 |
| --- | --- | --- |
| ① A0 Sol 기준선 | 현행. 한 번의 Sol 호출 안에서 판정·추출·설명을 수행. 로그 태그만 기능별로 분리하고 호출 횟수는 바꾸지 않음 | 현재 구조의 전체 업무 성공·비용·지연은 어느 수준인가 |
| ② Luna 통합 처리 → 필요시 Sol | Luna 1회가 대화 판정과 구조화 추출을 함께 수행. 승격 신호(혼합·모호·규칙 요청·문맥 의존·판단 충돌)면 Sol이 원래 요청과 허용 문맥을 다시 해석 | 저렴한 1회 호출로 처리되는 범위는 어디까지인가. 승격률과 통과 오류율은 얼마인가 |
| ③ 결정 모델 게이트 → Luna 또는 Sol | 게이트(Luna enum, Clef, Jev 중 어댑터로 교체)가 대화 유형과 "혼합·모호인가"를 판정한 뒤 Luna 또는 Sol로 분기 | 별도 게이트가 추가 비용·지연만큼 도움이 되는가. ②와의 차이로 게이트 효과를 분리 |

②·③ 공통 규칙:

- **지속 규칙 저장 동작은 서버가 Luna 경로에 허용하지 않는다.** 규칙 요청은 규칙 전용 경로(Sol)로만 가며, 그 경로에서 사용자 지시·적용 범위·예외를 검사한다.
- **권한·대상·최신 상태 검사 실패는 보류다.** 승격 대상이 아니다. 대상 해석이 모호한 경우만 Sol 재해석 후보다.
- 결과 설명을 위해 Sol을 다시 호출하면 그 비용·지연을 전체 처리에 포함한다(세부 구조 §3.1).
- 잡담·범위 밖 판정 항목에는 새 자료 조회·A1~A4 호출·외부 실행·규칙·선호 변경을 허용하지 않는다(상세 설계 A0.1). 혼합 발화에서 인사 부분 때문에 업무 요청을 버리지 않는다(세부 구조 §5.3).

### 3.3 백엔드가 잡는 오류와 통과시키는 오류

| 백엔드가 검사할 수 있는 것 | 형식·권한 검사를 통과할 수 있는 오류 |
| --- | --- |
| 존재하지 않는 메일 ID | 접근 가능한 다른 메일을 잘못 선택 |
| 허용되지 않은 계정 접근 | 허용 계정 안에서 사용자의 대상을 오해 |
| 필수 필드 누락 | 요청 두 개 중 하나만 처리 |
| 지원하지 않는 실행 동작 | 지원하는 동작을 잘못 선택 |

Structured Outputs는 출력 형식 준수를 보장하지만 의미 정확성은 보장하지 않는다. 오른쪽 열의 오류는 사용자 수정률만으로 찾기 어렵다. 사용자가 알아채지 못한 누락이 있기 때문이다. 따라서 **검사를 통과한 Luna 결과 중 실제로 잘못된 결과**를 사람 검수로 측정한다.

## 4. 측정 지표

| 지표 | 정의 | 왜 필요한가 |
| --- | --- | --- |
| Sol 승격률 | ②·③에서 Luna 처리 후 Sol로 넘어간 요청 비율. 세부 구조 §10.1 기준으로 A1~A3의 Sol 재검토율과 별도 집계 | 비용·지연의 주 변수 |
| Luna 통과 결과 중 실제 오류율 | 형식·권한 검사를 통과한 Luna 결과 중 사람 검수에서 오류로 판정된 비율. 잘못된 대상 선택·요청 항목 누락·지원 동작 중 잘못된 선택으로 세분 | 백엔드가 못 잡는 오류 |
| 상류 통과율 | Sol 또는 확인 질문이 필요했던 요청을 Luna(또는 게이트)가 단일·명확으로 통과시킨 비율 | 승격 신호·게이트의 재현율. 게이트 오류는 하류에서 복구되지 않음 |
| 요청 항목 누락률 | 혼합 요청에서 처리·안내·확인 중 어느 것도 받지 못한 항목 비율 | "고마워, 그리고 답장도" 유형 |
| 잘못된 대상 선택률 | 허용 범위 안에서 사용자 의도와 다른 메일·업무·계정을 고른 비율 | 형식 검사 통과 오류의 대표 |
| 잘못된 거절률 | 정상 업무 요청을 범위 밖·잡담으로 처리한 비율 | 상세 설계 §11의 기존 지표 |
| 지연 3종 | 잡담 응답 완료, 요청 해석 완료, A4 초안까지 전체 완료. 게이트 직렬 추가분과 Luna→Sol 승격의 이중 처리 시간을 분리 기록 | 구성별 체감 변화 |
| 비용 | 실제 사용량 기준. 캐시 읽기·쓰기, 추론 토큰, 재시도, 결과 설명 호출, 게이트 호출 포함. 누락 사용량을 0으로 처리하지 않음 | 추정치 교체. 세부 구조 §10.1 |

라우팅 정확도에 중요 메일 재현율 98%·정밀도 90% 목표를 그대로 치환하지 않는다(세부 구조 §11.2). A0 계층형의 수용 수치는 평가 세트의 분포를 본 뒤 정한다.

## 5. 평가 세트에 반드시 넣을 사례

세부 구조 §11.2의 사례에 더해 다음을 포함한다. 조정용·평가용 자료를 분리하고 사용자·대화가 두 집합에 섞이지 않게 한다.

| 사례 | 노리는 오류 |
| --- | --- |
| "이번에는 초안만 만들고, 앞으로 이런 메일은 먼저 알려줘" | 단일로 보이는 혼합(초안 + 규칙). 게이트·Luna가 초안 단일로 통과시키는지 |
| "지난번에 거절한 조건은 빼고 다시" | 긴 대화 문맥 계승. 단일·명확으로 오판 |
| "A사는 중요하지만 행사 광고는 일반으로" | 여러 예외가 걸린 단일 요청. 규칙 전용 경로로 가는지 |
| "고마워, 그리고 답장도 써줘" | 단순 혼합. Luna로 충분한지, 인사 때문에 업무를 버리지 않는지 |
| 허용 계정 안에 비슷한 메일이 여러 개인 상태의 "이거 답장해줘" | 접근 가능한 다른 메일 선택. 형식 검사 통과 오류 |
| 권한이 해제된 계정·삭제된 메일을 대상으로 한 요청 | 보류로 끝나는지. Sol 승격으로 우회하지 않는지 |
| "게임 공략 써줘"와 "이 메일 초안 써줘"가 섞인 발화 | 범위 밖 안내와 업무 처리의 항목별 분리 |
| "이거 다 정리해줘" | 모호. 확인 질문으로 가는지, 임의 실행하지 않는지 |

## 6. 비용 추정의 조건

기존 분석의 가정(월 180회 발화, 잡담 25%, 핵심 요청 중 Sol 30%, 호출당 토큰·캐시, 2026-09 단가)을 그대로 쓰면 A0 월 비용은 다음처럼 계산된다.

| 처리 방식 | 사용자당 월 A0 계산값 |
| --- | --- |
| ① 전부 Sol | 약 $0.75 |
| ③ 게이트에서 Sol 대상은 바로 Sol로 분기 | 약 $0.20 |
| ② 핵심 요청을 모두 Luna로 처리한 뒤 30%를 Sol로 승격 | 약 $0.21 |

- 이 값은 **조건부 추정**이다. 실제 승격률, 추론 토큰, 캐시 적중·쓰기, 재시도, 결과 설명 호출에 따라 달라진다.
- 기존 분석 문서의 누적 절감률(S3 −29%, 계층형 포함 −43%)에는 A1·A2 처리 비율과 Sol 재검토율 감소 가정이 포함돼 있다. 세부 구조 §10.2가 밝힌 대로 C안 선택이 이 수치를 성과로 승인한 것이 아니다.
- 지연도 같다. 게이트를 직렬로 추가하면 그 시간이 먼저 들고, Luna 뒤 Sol로 승격하는 요청은 두 모델의 처리 시간을 모두 부담한다. §4의 지연 3종을 각각 측정한다.

## 7. 진행 순서

1. **기준선 고정**: ① 구성의 코드 경로·프롬프트·추론 설정을 고정하고 로그 태그를 기능별로 분리한다. 호출 횟수는 바꾸지 않는다.
2. **평가 세트 준비**: §5 사례를 포함해 조정용·평가용으로 분리한다. 합성 자료부터 시작하고 실제 베타 자료는 처리 조건을 갖춘 뒤 사용한다([개인정보 검토](11-Jev와-외부-AI-개인정보-검토-v1.0.md)).
3. **격리 평가**: ②·③을 같은 세트로 실행한다. 운영 응답은 비교 호출을 기다리지 않는다. 사람 검수로 §4 지표를 채운다.
4. **경계 결정**: 승격 신호와 Luna 처리 범위, 게이트 채택 여부를 지표로 정한다. 운영 몇 달을 기다릴 필요는 없다.
5. **제한 적용 검토**: 검증된 범위·임계값·복귀 비용·지연을 제시하고 사용자 선택을 받는다(세부 구조 §11.3). 초기 모델 배분 변경은 이 시점의 결정 사항이다.

## 8. 결정이 필요한 질문 (사용자 선택)

| 질문 | 추천안 | 대안 | 영향 |

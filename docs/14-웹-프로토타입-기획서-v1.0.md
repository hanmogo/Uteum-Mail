## 1. 목적과 결정 상태

첫 프로토타입은 **가상 메일과 정해진 응답으로 전체 핵심 여정을 실제로 조작해 보는 웹 화면**이다. 사용자가 여러 계정의 중요한 메일을 찾고, 근거를 확인하고, 업무·초안·규칙·수신 관리를 이어갈 수 있는지 검토한다. 화면과 동작의 검증 결과를 다음 서버·AI 구현의 입력으로 사용한다.

| 구분 | 내용 |
| --- | --- |
| 사용자 확정 | C안: 기존 Luna·Sol 운영 경로를 유지하고 Jev는 결과 미반영 평가 후 검증된 범위부터 도입 |
| 사용자 확정 | 첫 프로토타입은 화면·상호작용부터 구현. 실제 메일·모델·서버·DB 연결은 화면 검토 이후 |
| 사용자 확정 | 시작 설정, 오늘, 통합 메일, 업무, 초안, 비서·검색, 규칙, 수신 관리, 설정의 전체 핵심 여정 |
| 사용자 확정 | 밝고 간결한 업무형. 중립색과 한 가지 강조색, 목록·상세 중심의 반응형 화면 |

### 1.1 검증할 질문

- 처음 온 사용자가 가상 체험, AI 사용, 메일만 보기의 차이를 이해하는가?
- 중요한 메일과 오늘 처리할 업무를 찾고 원문으로 돌아갈 수 있는가?
- 읽음·답장·업무 완료, 광고 분류·중요도·수신 해제의 차이가 화면에서 드러나는가?
- 짧은 요청과 버튼 어느 쪽으로 시작해도 같은 대상·규칙·업무를 다루는가?
- 처리 대기·실패·권한 미확인 상태를 정상 완료와 구분하고 다음 행동을 찾을 수 있는가?

사용성 검토에서는 수행한 시나리오, 막힌 위치, 도움 필요 여부, 잘못 이해한 문구와 수정 의견을 기록한다. 사용자 수·성공률·소요 시간의 합격 수치는 이번 문서에서 새로 확정하지 않는다.

### 1.2 단계별 검증 범위

| 단계 | 다룰 내용 | 완료로 볼 수 있는 결과 |
| --- | --- | --- |
| 현재 문서화 | 이 기획서, 구현 계획서, 기존 결정의 정합성 | 화면·행동·상태와 구현 순서를 이어서 확인 가능 |
| 첫 화면 프로토타입 | 가상 데이터와 모의 처리로 S1~S9 연결 | 화면 사용 흐름과 상태 변경을 반복 검증 |
| 후속 서버·AI 연결 | Spring·FastAPI·PostgreSQL·작업 처리, 기존 Luna·Sol 기준선 | 실제 기능·장애 복구·품질·비용 측정 |
| Jev 비교·제한 적용 | 합성 자료부터 결과 미반영 평가, 조건 충족 후 제한된 실제 자료 평가 | 검증 결과와 사용자 선택에 따라 운영 적용 범위 결정 |

화면에서 보여주는 분석·지연·발송·연동 결과는 시연값이다. 실제 AI 정확도, 절감률, 제공사 동기화, 가용성 또는 복구 목표를 달성했다는 근거로 사용하지 않는다. Spring·FastAPI 분리 등 서비스 스택과 공개 MVP의 P0·P1 목표는 유지한다.

## 2. 체험 범위와 공통 원칙

### 2.1 가상 기능의 경계

| 항목 | 첫 프로토타입 동작 |
| --- | --- |
| 가입·인증 | 가상 프로필로 체험. 실제 비밀번호·OAuth·앱 비밀번호를 입력받지 않음 |
| 제공사 연결 | Gmail·네이버·다음·카카오메일의 가상 계정 선택과 연결 상태 전환 |
| 메일·첨부 | 준비한 합성 메일과 예시 첨부의 목록·본문·미리보기. 실제 메일함이나 사용자 파일을 가져오지 않음 |
| 비서·분류·초안 | 준비된 결과와 지원 입력의 모의 처리. 외부 AI·임베딩 호출 없음 |
| 발송·수신 해제 | 가상 자료와 처리 이력만 변경. 실제 SMTP·제공사 API·해제 주소를 호출하지 않음 |
| 검색 | 현재 체험 계정·필터 범위의 가상 제목·본문·상대·업무 키워드 검색 |
| 보관·삭제 | 해당 브라우저의 프로토타입 자료만 변경. 운영 보관·백업·외부 업체 삭제의 구현으로 표시하지 않음 |
| 실행 환경 | 로컬 웹 개발 서버에서 확인. 유료 인프라·공유 배포·결제·캘린더·모바일 앱은 후속 범위 |

공통 안내는 “가상 데이터 체험 · 실제 계정 연결과 발송은 이루어지지 않습니다”로 둔다. 고객 기능 화면에는 에이전트 이름이나 내부 모델 경로 대신 “확인 중”, “초안 준비”, “검토 필요”처럼 결과 중심의 표현을 쓴다.

### 2.2 상태와 실행 원칙

1. 메일 유형·중요도·업무 상태는 별도로 저장하고 표시한다. 중요한 광고도 중요 보기와 전체 목록에서 확인한다.
2. 읽음·보관·모의 발송만으로 업무를 완료하지 않는다. 업무 완료는 별도 사용자 동작으로 처리한다.
3. 업무 후보·마감 변경·완료 제안은 원문과 함께 보여주고 채택·수정·거절할 수 있게 한다.
4. 사용자가 명확히 지정한 대상·동작은 반복 승인 없이 모의 실행한다. 대상·범위·효과가 모호할 때 필요한 부분만 확인한다.
5. 초안 생성과 모의 발송을 구분한다. 최종 발신 계정·수신자·본문을 확인할 수 있는 편집기에서 발송을 명시적으로 눌러야 한다.
6. 분석 대기·실패를 “남은 업무 없음”으로 표시하지 않는다. 연결 만료를 “새 답변 없음”으로 표시하지 않는다.
7. 비서 결과와 직접 편집은 같은 상태에 반영한다. 사용자 편집 중 늦게 도착한 모의 초안으로 내용을 덮어쓰지 않는다.
8. AI 끄기, 메일 계정 연결 해제, 자료 삭제, 마케팅 해제는 서로 다른 동작이다.

## 3. 화면 구성과 디자인

### 3.1 탐색과 반응형 구성

- 첫 화면은 ‘오늘’을 기준으로 하고, 시작 설정 체험으로 진입하는 별도 동선을 제공한다.
- 기본 메뉴는 오늘, 통합 메일함, 할 일, 서비스·수신 관리, 검색, 분류 규칙, 설정이다. 새 메일 작성과 비서는 공통 진입점이다.
- 데스크톱은 탐색 메뉴·목록·상세를 함께 보여주고 비서는 필요할 때 연다. 좁은 화면에서 상세와 비서가 동시에 겹치지 않게 한다.
- 모바일은 목록에서 상세로 이동하고 뒤로 가면 계정·필터·선택 문맥을 복원한다. 비서는 별도 화면 또는 전체 높이 패널로 연다.
- 회색 계열 배경·본문과 한 가지 강조색을 사용한다. 오류·완료 등 의미색은 텍스트와 함께 표시한다.
- 폼에는 이름과 설명을 연결하고, 모달·패널 열기와 닫기에서 키보드 포커스를 이동·복원한다.

정확한 색상·간격·글자 크기는 공통 토큰으로 관리하는 구현 세부값이다. 별도의 브랜드 확정이나 다크 모드 지원 결정으로 확대하지 않는다.

3장의 화면표와 7장의 기술 확인은 2026-10-04에 구현한 초기 프로토타입 기준이다. 2026-10-06 사용자가 제시한 실제 개발용 UX 변경은 9장과 웹앱 기획서 6장을 따르며, 현재 화면에 적용한 것으로 표시하지 않는다.

## 5. 가상 자료와 시나리오 운영

### 5.1 준비할 자료

- 제공사 4종의 가상 계정과 개인용·업무용·혼합 용도. ‘바로 체험’은 준비된 설정으로, ‘처음부터 체험’은 연결 전 상태로 시작한다.
- 견적 요청, 자료 전달 약속, 부분 답변, 자동 회신, 기한 변경, 중요 뉴스레터, 일반 광고, 주문·보안 알림을 포함한 대화.
- 한 메일의 복수 업무, 하나의 업무에 연결된 복수 메시지, 마감 없음·모호한 기한·확인 예정일 사례.
- 초안, 분류 규칙, 연동·수동 확인·메일 근거의 구독 목록, 준비된 예시 첨부와 처리 이력.
- 실제 개인을 식별하지 않는 이름·본문과 `.example` 주소. 계정 이름·제공사 표시는 체험용임을 명시한다.

### 5.2 반복 가능한 체험

시연 기준 시각은 **2026-10-03 09:00, Asia/Seoul**로 고정하고 ‘오늘’, 기한 경과, 답변 대기의 자료를 이 시각 기준으로 구성한다. 이는 운영 서비스의 시계 정책이 아닌 가상 자료의 기준이다. 시연용 지연을 모델 응답 시간으로 보고하지 않는다.

체험 도구에서 정상, 빈 목록, 분석 대기·실패, 연결 만료, 일부 수신 해제 실패, 발송 결과 미확인 시나리오를 선택한다. 무작위 오류를 발생시키지 않는다. 시나리오 전환이 현재 체험 자료를 초기화하는 경우 버튼 설명에 그 효과를 표시한다.

가상 변경은 버전이 있는 브라우저 저장소에 유지한다. 데모 초기화는 가상 메일·업무·초안·규칙·설정·처리 이력을 함께 원본 상태로 복원한다. 저장을 사용할 수 없는 환경에서는 현재 화면 내 체험을 제공하고 새로고침 시 유지되지 않음을 안내한다.

## 6. 시작 설정·중단·삭제 표현

[기획서 7.1](07-웹앱-기획서-v1.6.md#71-처음-사용하기)과 [사용자 동의 시나리오](13-개인정보-법률-확인과-사용자-동의-시나리오-v1.0.md)의 확정 분기를 그대로 체험한다.

- 가상 제공사 인증만 끝나면 시작 설정 대기로 표시한다. 모의 수집·분석은 다음 선택에 따라 시작한다.
- 과거 분석의 최근 30일 제안, 새 메일 자동 분석, 동기화 범위와 보관 기간을 각각 표시한다.
- 미정인 업체 계약·국가·보유 기간·동의 문구는 검토용 예시임을 표시한다. 임의의 실제 운영 값을 채우거나 출시용 확정 약관으로 제시하지 않는다.
- AI 끄기는 새 모의 분석을 중단하고 이미 저장된 결과의 삭제와 구분한다. 연결 해제는 해당 계정의 새 모의 수집을 중단한다.
- 자료 삭제는 선택한 가상 계정의 원문·파생 결과·검색 참조를 함께 제거하고 원문 없는 이력을 구분한다. 다른 계정의 자료는 유지한다.
- 개인정보 동의 철회와 실제 업체·백업 삭제는 후속 서버·운영 검증 대상이다. 브라우저 자료 삭제로 완료됐다고 설명하지 않는다.

## 8. 이후 서버·AI 구현으로 넘길 내용

화면 검토 후 실제 계정·권한·동기화·공용 API·작업 복구를 구현하고 기존 Luna·Sol 구성의 기준 성능을 측정한다. Jev 평가는 합성 자료로 시작하며 실제 베타 메일을 보내기 전에 해당 처리에 필요한 계약·공개·안내·이전 근거를 확인한다. 평가 결과는 운영 상태에 반영하지 않고 운영 응답도 비교 호출을 기다리지 않는다.

판단·근거·모델 버전·사용량은 공통으로 기록하되 점수 제공 여부와 의미, 임계값·보정은 공급자별로 구분한다. `logprobs` 사용과 정확한 호출 설정은 후속 실험에서 검증한다. C안의 상세 기준은 [스택 보고서 9.3](06-기술-스택-선택-비교-보고서-v1.0.md#93-ai-판단추출과-비용품질-관찰)과 [결정모델 구조](12-에이전트+결정모델-세부-구조-v1.0.md)를 따른다.

실제 연결·평가에 필요한 선택은 [후속 결정 목록](10-후속-결정-목록-v1.0.md)에서 추천안과 함께 질문한다. 화면 프로토타입의 가상 결과를 운영 기본값·법률 검토 완료·AI 품질 보증으로 전환하지 않는다.

## 2. 전제와 가정

### 2.1 문서에서 가져온 확정·설계 사항

- 5개 에이전트와 초기 모델 배분: A0 오케스트레이터·A4 응답 작성은 Sol, A1 메일 이해·분류·A2 문맥·업무 추적·A3 서비스·수신 관리는 Luna, 조건부 Sol 재검토. (사용자 확정 2026-09-27)
- 모델 도입 순서: Luna·Sol 기준 성능 → 동일 한국어 메일로 Jev 비교(미반영) → 중요 메일 누락이 늘지 않는 검증 범위부터 적용. (사용자 확정)

- 날짜 계산·확정 규칙 적용·화면 갱신은 모델 없이 코드가 수행. 메일 목록 표시는 AI 완료를 기다리지 않음. (상세 설계 §2, 기획서 9.7)

## 3. 현재 구조에서 결정 모델이 들어갈 수 있는 지점

### 3.1 역할별 분해

| 지점 | 현재 | 결정 모델로 대체 가능 | 생성 LLM이 남는 부분 |
| --- | --- | --- | --- |
| A1 메일 이해·분류 | Luna가 4개 판단·요약·행동 후보·근거를 한 번에 생성 | 4개 판단 + 근거 구간 ID 선택(`none` 허용). 상세 설계의 `mail_decision.v1` 형식과 일치 | 요약, 행동 언급 후보, 일정 표현 추출. `task_signal`·`needs_reply`·`importance` 중 하나라도 yes/important일 때만 호출 (약 35%) |

### 3.2 설계 원칙과의 정합성

- 상세 설계 §8 "Luna의 자기 평가 점수만으로 재검토 여부를 결정하지 않는다": Jev의 확률은 모델이 서술한 자기 평가가 아니라 보정을 목표로 만들어진 출력이므로 성격이 다르다. 다만 §9의 "confidence를 정답률 보증이나 실행 승인으로 사용하지 않는다"는 그대로 유지하며, 확률은 **라우팅(폴백·검토 전환) 신호**로만 쓴다.
- 상세 설계 §2 "날짜 계산·확정 규칙 적용은 모델 없이 수행": Jev는 산술·날짜 계산·임계값 비교를 하지 못하므로, 코드가 먼저 계산해 state에 넣는 기존 원칙과 정확히 맞는다.
- 상세 설계 §10 "모델이 없는 근거 ID 생성 → 거절": Jev는 제시된 구간 ID 중에서만 선택하므로 이 실패 유형이 구조적으로 사라진다.
- Jev는 질문 여러 개를 한 호출에 넣을 수 있어 A1의 4문항 + 근거 선택이 1회 호출이다. OpenAI Decisions API는 현재 공개 정보상 1문항/1호출이며 아직 일반 공개 전이므로, 이 구조에는 Jev가 더 맞는다. Decisions API는 공개 후 같은 어댑터 뒤에서 비교한다.

### 3.3 A1을 "결정"과 "추출"로 분리하는 안

```
새 메일 → 코드: 중복·분석 제외·확정 규칙
       → Jev 결정: mail_type, importance, needs_reply, task_signal, evidence_segment
       → 코드: 확률 임계값 검사
            ├ 확실 구간 → 결과 저장 (광고·뉴스레터 대부분 여기서 종료)
            ├ 경계 구간 또는 규칙 관련 → Luna 추출 + 판단 재확인
            └ 규칙 충돌·근거 불일치 → Sol 재검토 (1회 상한 유지)
       → task_signal / needs_reply / important 중 하나라도 해당 → Luna 추출(요약·행동 후보)
       → A2 조건 충족 시 A2
```

- 현재 설계는 광고·뉴스레터에도 요약과 행동 후보를 생성한다. 결정이 먼저 걸러주면 생성 호출이 약 3분의 1로 줄어든다.
- 초기 분석(ONB-04)은 "결정만" 먼저 돌려 중요 메일 보기를 빠르게 채우고, 추출은 사용자가 해당 메일·업무 화면을 열 때 지연 실행할 수 있다.

### 4.2 현재 설계(S0)의 비용 구성

| 항목 | 월 비용 | 비중 |
| --- | --- | --- |
| A1 Sol 재검토 (1,440건 × 10%) | $0.90 | 35% |
| A0 Sol (180발화) | $0.75 | 29% |
| A4 초안 Sol (45건) | $0.37 | 14% |
| A1 Luna 분류 (1,440건) | $0.28 | 11% |
| A2 Sol 재검토 | $0.19 | 7% |
| A2 Luna | $0.04 | 2% |
| 임베딩·A3 | $0.03 | 1% |
| 합계 | $2.56 | Sol 합계 86% |

- Luna 분류 전체가 $0.28인데, 그중 10%를 Sol이 재검토하는 비용이 $0.90이다. **Sol 재검토 1회($0.0062) = Luna 분류 32회 = Jev 결정 114회**다.
- 따라서 "Luna를 Jev로 바꾸는 것"보다 "Sol이 몇 %의 메일을 다시 보는가"가 비용을 결정한다. 결정 모델의 가치는 단가 차이보다 **재검토 비율을 안전하게 낮추는 신호를 제공하는 데** 있다.

### 4.3 A1 Sol 재검토율 민감도 (A1 경로만, 사용자당 월)

| 재검토율 | Luna 분류 경로 | Jev 결정 경로 |
| --- | --- | --- |
| 3% | $0.55 | $0.44 |
| 6% | $0.82 | $0.71 |
| 10% | $1.18 | $1.07 |
| 15% | $1.63 | $1.52 |

- 재검토율 1%p = 사용자당 월 약 $0.09. Luna↔Jev 교체 효과($0.11)와 맞먹는다.
- Jev 가격이 5배가 되어도 S3 절감률은 29% → 약 27%로 거의 변하지 않는다. 비용 구조 자체는 가격 변동에 견고하다.
- **단서(2026-10-06)**: S1~S4의 절감률에는 A1·A2 처리 비율과 Sol 재검토율 감소(10% → 6%) 가정이 포함돼 있다. 재검토율은 Jev 확률만으로 낮추지 않고 관찰 가능한 신호와 평가 성능으로 정한다(세부 구조 §6.2). 실제 승격률·추론 토큰·캐시 적중·재시도·결과 설명 호출에 따라 값이 달라지므로, 13.2의 실측값이 나오면 이 표를 대체한다.

### 4.4 요금제 목표 대비

기획서 13.2의 "사용자당 AI·사용량 연동 인프라 변동비 ≤ 구독매출 30%" 목표에 AI 비용만 대입한 값이다. 인프라 변동비는 포함하지 않았다.

| --- | --- | --- | --- |

| 19,900원 | 5,970원 | 60% | 43% |
| 29,900원 | 8,970원 | 40% | 29% |

- 9,900원에서는 현재 설계가 AI 비용만으로 상한을 넘는다. 결정 모델을 적용해도 인프라 변동비를 더하면 빠듯하다. 결정 모델 도입은 최저 가격대의 **성립 조건**에 가깝다.
- 가정한 메일량(하루 40통)이 많은 편이므로, 실제 분포에서 중앙값 사용자는 이보다 낮을 수 있다. 다만 기획서 11.3이 지적한 "메일량이 많은 사용자"가 바로 이 구간이다.

## 5. 성능 하락 예측

### 5.1 전제

- 공개 벤치마크는 영어·소규모다. Jev 도구 호출 위험 분류 n=60에서 정확도 91.7%(모호 사례 71.4%), 기대 보정 오차 0.05~0.07, **틀린 답은 전부 신뢰도 0.13~0.79 구간**. LiteLLM 라우터 벤치마크 n=80에서 Jev 95% vs Haiku 프롬프트 74%. 작성자들 모두 "자기 프롬프트·라벨에 한정된 결과"라고 명시했다.
- 한국어 메일 결과는 없다. 아래 수치는 영어 결과를 한국어·혼합 메일에 보수적으로 할인한 기대치이며, 상세 설계 §9의 2단계 비교(500개 대화 평가 세트)로 대체되어야 한다.

### 5.2 지점별 예상

| 지점 | Jev 단독 (Luna 대비) | 확률 임계값 + Luna/Sol 폴백 적용 시 | 위험 요인 |
| --- | --- | --- | --- |
| A1 `mail_type` 9분류 | −2~5%p | −0~2%p | 광고·거래·보안은 패턴이 뚜렷해 동등 이상 가능. `mixed`/`unknown` 경계가 약점 |
| A1 `importance` (사용자 규칙 반영) | −3~6%p | 재현율 유지, 정밀도 −1~2%p | 자연어 규칙·예외를 state 텍스트로만 받고 추론하지 않음. 규칙이 걸린 메일은 Luna로 보내는 것이 안전 |
| A1 `needs_reply` / `task_signal` | −2~4%p | −0~1%p | 요청 문장 탐지는 분류기의 강점 영역 |
| A2 연결 대상 선택 | 후보 ≤3개면 동등, 다수면 −5%p 이상 | 동등 | 상세 설계가 이미 "연결 가능한 업무가 여러 개면 Sol"로 정의. 그 조건을 확률 분산으로 감지 |
| A0 잡담 게이트 | 핵심 업무를 잡담으로 오판 1~3% | 임계값 0.9 이상에서 1% 미만 | 오판 비용은 사용자가 다시 말하는 불편. "메일 단어 없다고 거절 금지" 원칙상 임계값은 보수적으로 |
| 형식 오류·근거 ID 날조 | 구조적으로 0 | 0 | 개선 항목 |

### 5.3 재현율 98% 목표를 지키는 임계값 설계

- 중요도는 비대칭 임계값을 쓴다. `P(important) ≥ 0.9` → Jev 결과 채택. `P(important) ≤ 0.05` → Jev 결과 채택. **그 사이는 전부 Luna 추출·재확인 또는 Sol로** 보낸다.
- 재현율을 깎는 오류는 "중요한데 아니라고 한 것"이므로, "아니다"를 Jev 혼자 확정하는 조건을 가장 엄격하게 둔다. 이 설계에서 메일의 15~25%가 폴백으로 가고, 혼합 정확도는 Luna 기준선의 ±1%p 안에 들 것으로 예상한다.
- 사용자 규칙이 적용 대상인 메일(규칙의 발신자·주제 조건에 걸리는 메일)은 임계값과 무관하게 Luna 경로를 유지한다. 규칙 예외 해석은 추론이 필요한 영역이다.
- "틀린 답은 낮은 신뢰도 구간에 있다"는 성질이 한국어에서도 유지되는지가 2단계 비교의 첫 확인 항목이다. 유지되지 않으면 Jev 적용 범위를 광고·거래·보안 유형으로만 좁힌다.

### 5.4 2단계 비교에서 추가로 기록할 지표 (제안)

- 신뢰도 구간별(0.0~0.5 / 0.5~0.8 / 0.8~0.9 / 0.9~1.0) 정확도와 건수 → 보정 여부와 임계값 결정의 근거.
- 임계값별 폴백 비율과 그때의 중요 메일 누락 수 → 비용·재현율 곡선.
- 규칙 적용 메일 / 미적용 메일을 분리한 정확도.
- 메일 길이(Jev 32K 한도 대비)와 잘라낸 비율.

## 6. 지연시간 분석

서울 발신, 두 공급사 모두 해외 리전으로 가정(왕복 0.15~0.2초 포함), p50 기준 추정이다. Jev 공개 측정값은 p50 130~420ms로 편차가 있다.

| 경로 | 현재 (Luna/Sol) | 결정 모델 적용 | 사용자 체감 |
| --- | --- | --- | --- |
| 새 메일 1통 분류 | 1.5~2.5초 | Jev 0.4~0.7초 (+35%는 Luna 추출 1.2초) | 목록 표시는 이미 AI와 분리. "중요" 배지가 붙는 시점만 빨라짐 |
| 가입 초기 분석 1,200통 (동시 10) | 약 4분 | 약 1분 (결정만), 추출은 지연 실행 | ONB-04 첫 가치 경험 시간 단축 |
| 규칙 변경 재분류 300통 (동시 10) | 약 60초 | 약 15초 | RUL-05 진행률 체감 개선 |
| 비서 발화 → 잡담 응답 | Sol 2.5~4초 | Jev 0.5초 + Luna 0.8초 ≈ 1.3초 | JRN-10 잡담 왕복이 자연스러워짐 |
| 비서 발화 → 핵심 업무 | Sol 2.5~4초 | **+0.5초** (게이트 오버헤드) | 소폭 악화. 아래 선택지 참고 |
| A2 업무 연결 제안 | 1.5~2.5초 | 0.5초 (+50%는 날짜 추출 1초) | 업무 카드 생성 체감 개선 |
| 답장 초안 (목표 p95 30초) | Sol 6~12초 | 변화 없음 | — |

- A0 게이트의 +0.5초는 게이트와 Sol 호출을 병렬로 띄우고 잡담 판정 시 Sol 결과를 버리면 0이 된다. 대신 잡담 25%의 Sol 비용 절감이 사라진다. 지연 우선이면 병렬, 비용 우선이면 직렬이며 사용자 선택 사항이다.
- Jev는 단일 공급자·얼리 액세스이므로, 상세 설계 §8의 "비교 요청이 느리거나 실패해도 운영 응답을 기다리게 하지 않는다"를 3단계 운영 적용 후에도 **타임아웃 시 Luna 폴백**으로 유지한다.
- p95는 양쪽 다 네트워크 변동이 지배한다. 13.2대로 서버 자체 지연과 외부 모델 지연을 분리 측정한다.

## 8. 비용 외 고려 사항

### 8.1 데이터 처리와 법적 조건

- 기획서 12장의 "해외 LLM·클라우드" 항목에 TypeSafe가 두 번째 해외 처리업체로 추가된다. 상세 설계 §9의 "실제 사용자 자료의 비교는 TypeSafe로의 처리까지 허용된 범위에 한정"이 이미 이를 전제한다.
- 2단계 비교 전 확인 항목(제안): TypeSafe의 학습 미사용·보관·삭제 조건, 처리 지역, 보안 인증, Gmail 제한 권한 데이터의 제3자 전송이 Limited Use에 부합하는지, 네이버·다음·카카오 메일의 외부 AI 처리 조건.
- 메일 주소·전화번호·계좌 등 식별자를 코드로 마스킹한 뒤 Jev에 보내면 분류 품질 손실 없이 전송 범위를 줄일 수 있다. 분류에는 "누가"보다 "무슨 내용"이 중요하다.

### 8.2 공급자 리스크

- Jev는 얼리 액세스·단일 공급자·스타트업이다. Luna 폴백을 항상 유지하고(상세 설계 3단계의 복귀 절차와 일치), 가격·약관 변경 시 §4를 재계산한다.
- OpenAI Decisions API는 공개 후 같은 어댑터로 비교한다. 1문항/1호출 구조라면 A1에 4회 호출이 필요해 Jev보다 지연·비용이 불리할 수 있다.

## 10. 계산 재현

아래 Python 스크립트는 §4의 표를 그대로 생성한다. 가정값만 바꿔 재계산할 수 있다.

```python
LUNA_IN, LUNA_CACHED, LUNA_OUT = 0.10, 0.01, 0.50
SOL_IN,  SOL_CACHED,  SOL_OUT  = 2.00, 0.20, 10.0
JEV_IN = 0.042
KRW = 1400

def luna(n, cached, fresh, out): return n*(cached*LUNA_CACHED + fresh*LUNA_IN + out*LUNA_OUT)/1e6
def sol(n, cached, fresh, out):  return n*(cached*SOL_CACHED  + fresh*SOL_IN  + out*SOL_OUT )/1e6
def jev(n, tokens):              return n*tokens*JEV_IN/1e6

MAILS=1200; RULE_HIT=0.30; AI_MAILS=MAILS*(1-RULE_HIT); RECLASS=600; BACKFILL=1200
A2_RATE=0.20; UTTER=180; SMALLTALK=0.25; DRAFTS=45; A3_SESS=5

A1_LUNA=(700,1100,160); A1_SOL=(700,1800,250); A1_JEV=1300; A1_EXTRACT=(500,1100,140)
A2_LUNA=(600,1600,200); A2_SOL=(600,2200,300); A2_JEV=1500; A2_EXTRACT=(400,900,100)
A0_SOL=(900,900,220);   A0_JEV=600; A0_SMALL=(300,300,60)
A4_SOL=(800,2000,400);  A3_LUNA=(600,2200,300); A3_JEV=1800

def scenario(a1, a2, a0_gate, a3, first_month=False):
    c = {}
    n = AI_MAILS + RECLASS + (BACKFILL if first_month else 0)
    if a1 == "luna":
        c["A1"] = luna(n,*A1_LUNA) + sol(n*0.10,*A1_SOL)
    else:
        c["A1"] = jev(n,A1_JEV) + luna(n*0.35,*A1_EXTRACT) + sol(n*0.06,*A1_SOL)
    m = AI_MAILS*A2_RATE
    c["A2"] = (luna(m,*A2_LUNA)+sol(m*0.15,*A2_SOL)) if a2=="luna" else (jev(m,A2_JEV)+luna(m*0.5,*A2_EXTRACT)+sol(m*0.10,*A2_SOL))
    c["A0"] = sol(UTTER,*A0_SOL) if not a0_gate else (jev(UTTER,A0_JEV)+luna(UTTER*SMALLTALK,*A0_SMALL)+sol(UTTER*(1-SMALLTALK),*A0_SOL))
    c["A3"] = (luna(A3_SESS,*A3_LUNA)+sol(A3_SESS*0.2,*A2_SOL)) if a3=="luna" else (jev(A3_SESS,A3_JEV)+luna(A3_SESS*0.3,*A3_LUNA)+sol(A3_SESS*0.1,*A2_SOL))
    c["A4"] = sol(DRAFTS,*A4_SOL)
    c["embed"] = (MAILS+(BACKFILL if first_month else 0))*700*0.02/1e6
    return sum(c.values()), c

for name,args in [("S0",("luna","luna",False,"luna")),("S1",("jev","luna",False,"luna")),
                  ("S2",("jev","jev",False,"luna")),("S3",("jev","jev",True,"luna")),("S4",("jev","jev",True,"jev"))]:
    t,_ = scenario(*args); print(name, f"${t:.2f}", f"{t*KRW:.0f}원")
```

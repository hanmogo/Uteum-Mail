## 1. 구현 결과

가상 메일과 정해진 비서 응답으로 화면 이동·편집·업무·규칙·수신 관리가 연결되는 웹 프로토타입을 구현했다. 같은 계정·메일·업무를 안정적인 ID로 연결하고 공통 상태의 변경을 관련 화면에 반영한다. 가상 자료는 버전이 있는 localStorage에 저장하며, 시나리오 전환과 초기화로 반복 체험할 수 있다.

| 화면 | 구현한 내용 |
| --- | --- |
| S1 시작·초기 설정 | 4종 제공사의 계정 추가 모의 처리, 개인·업무용, 분석 범위, AI 사용·메일만 보기·수집 대기 분기 |
| S2 오늘 | 중요 메일·오늘 확인할 일·답변 대기·기한 지난 업무, 계정 범위와 원문 이동, 미분석 안내 |
| S3 할 일·답변 대기 | 후보 채택·수정·제외, 기한 제안 채택·거절, 완료·복원, 부분 답변·자동 회신과 남은 요청 |
| S4 통합 메일 | 받은·보낸 메일·초안, 계정·유형·중요·읽음 필터, 대화·첨부 예시, 중요도·유형의 독립적인 수정 |
| S5 작성·초안 검토 | 새 메일·답장·전달, 초안 준비·편집·저장, 수신자·발신 계정 확인, 명시적 모의 발송, 결과 미확인 처리 |
| S6 검색·비서 | 가상 자료 키워드 검색, 현재 계정·메일 참조, 추천 요청·준비된 응답, 모호한 범위·미지원 입력 안내 |
| S7 설정·데이터 관리 | AI 끄기·연결 해제·자료 삭제의 다른 효과, 계정별 설정, 재연결, 데모 초기화 |
| S8 서비스·수신 관리 | 연동·수동 확인·메일 근거 출처, 마케팅 해제 접수·확인·실패·직접 설정, 부분 처리 결과 |
| S9 분류 규칙 | 조건·계정·예외·향후 적용, 일회성 표시와 지속 규칙, 수정·중지·재개·변경 영향 되돌리기 |

데스크톱은 탐색 메뉴·목록·상세와 필요할 때 여는 패널을 사용한다. 모바일은 목록→상세 전환과 전체 화면 초안·비서 패널을 사용한다. 모든 화면에 가상 체험 안내를 표시한다.

### 1.1 실행과 구현 경계

```bash
cd apps/web
npm ci
npm run dev
```

개발 주소는 [http://127.0.0.1:3000](http://127.0.0.1:3000)이다. 프로덕션 화면은 `npm run build` 후 `npm run start -- --port 3001`로 실행한다. [프런트엔드 안내](../apps/web/README.md)에 체험 흐름·저장 동작·스크립트를 기록했다.

실제 인증·메일 수집·발송·마케팅 해제·모델·임베딩·Spring·FastAPI·DB·SQS·S3 연결은 이번 구현에 포함되지 않는다. 준비된 비서 응답은 가상 접근 계층 안에서 생성한다. 공통 상태를 조회하고 Promise 기반으로 변경하는 경계는 프로토타입 내부 구조이며 최종 서버 API 계약으로 확정하지 않는다.

## 5. 남은 검토와 제한

### 5.1 사용자 화면 검토

2026-10-04 초기 화면의 기술 검증을 마쳤고, 2026-10-06 사용자가 통합 메일·홈 화면에 대한 첫 UX 피드백을 제공했다. 아래는 계속 확인할 항목이며, 전체 시나리오의 사용자 승인·후속 화면 재검증을 마친 것은 아니다.

1. 오늘→견적 메일→업무 후보→초안 편집→모의 발송→남은 업무 확인이 자연스러운지.
2. 중요한 광고·부분 답변·기한 제안·규칙 범위와 되돌리기를 이해할 수 있는지.
3. 수신 해제의 접수·확인·실패·직접 설정 필요가 구분되는지.
4. 모바일에서 목록·본문·초안·비서의 글자 크기와 조작이 편한지.
5. 시작 설정의 AI 사용·메일만 보기·수집 대기 안내가 이해되는지.

확정한 범위 안의 표현·배치 개선은 검토 결과에 따라 수정한다. 실제 제공사·모델 설정·임계값·예산·처리 계약 등 사용자의 추가 선택이 필요한 작업은 [후속 결정 목록](10-후속-결정-목록-v1.0.md)의 해당 항목부터 추천안과 대안을 제시한다.

사용자는 실제 프로젝트 개발 때 적용할 내용으로 제시했다. 피드백은 UX·UI 문서로 분리하고 [웹앱 기획서 6장](07-웹앱-기획서-v1.6.md#6-정보-구조와-핵심-화면)과 [프로토타입 기획서 9장](14-웹-프로토타입-기획서-v1.0.md#9-실제-개발용-사용자-ux-요구사항--2026-10-06)에서 연결했다. 3장의 테스트·빌드·캡처 기록은 초기 구현 당시의 결과이며 이번 문서 분리에서 소스·화면 변경은 수행하지 않았다.

### 5.2 개발 의존성 감사 기록

ESLint 10에서 React 플러그인의 `getFilename` 호환 오류가 발생해 ESLint 9.39.5를 사용했으며 린트가 통과했다. 전체 `npm audit`에는 개발용 의존성 경로 `eslint-config-next → @next/eslint-plugin-next → fast-glob → micromatch → braces`에서 **high 5개**가 표시됐다. 하위 문제와 이를 포함하는 상위 패키지를 합한 표시이며 운영 의존성 감사 결과는 0개다. [braces 관련 감사 항목](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)

감사 도구가 제시한 eslint-config-next 14.2.35 변경은 현재 Next.js 16 계열과 맞지 않아 적용하지 않았다. 호환되는 수정 버전을 확인하면 개발 도구를 갱신하고 린트를 재확인한다. 감사 경고와 타입·린트·빌드 통과는 서로 다른 검사 결과로 기록한다.

### 5.3 실제 연결과 작업 상태

이번 결과는 화면·가상 상태 동작의 구현이다. AI 정확도·비용 절감·동기화 신뢰성·운영 가용성은 실제 서버와 모델을 연결한 뒤 측정한다. 기존 C안의 Luna·Sol 기준 경로와 Jev 결과 미반영 평가는 유지하며, 이번에 모델을 호출하거나 모델 어댑터를 구현한 것은 아니다.

2026-10-04 초기 구현은 로컬 작업 트리에서 완료했고, 2026-10-06 사용자가 누적 작업의 커밋·푸시를 요청했다. 변경 이력은 [원격 저장소](https://github.com/hanmogo/Uteum-Mail)의 커밋 기록으로 확인한다. [프로토타입 진행 이슈](https://github.com/hanmogo/Uteum-Mail/issues/1)와 개별 구현 이슈는 열려 있다. 이 기록은 기술 검증 결과이며 사용자 검토 승인·실제 서비스 출시를 뜻하지 않는다.
